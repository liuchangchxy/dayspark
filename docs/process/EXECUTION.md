# 多代理执行工序守则 (EXECUTION.md)

> **定位**：本文件补全“意图 → 提交”之间的**执行工序**。分工：`AGENTS.md` 管意图与红线，`TESTING.md` 管测试、门禁与**停止准则（DoD）**，本文件管**任务如何被分解、交付、审查与收敛**。
> 三者冲突时：红线以 AGENTS 为准，停止以 DoD 为准，工序以本文为准。

---

## 0. 适用开关（先读，防过度设计）

- **规模旋钮**：单文件小改 / 单任务 = 只做一轮审查即可收敛，禁用完整闭环；**多任务成链或跨文件重构**才启用下述全流程。
- **宿主适配**：支持多子代理的宿主（如 Claude Code）走“派发模式”（实现者/审查者分角色）；单代理宿主（Cursor 等）降级为“自查清单模式”——同一套检查项，由同一个 AI 顺序自问自答，**不可跳过任何检查项**。
- **严重度统一（防两套阶梯混用）**：一切分级以 AGENTS/TESTING 的 **P0–P3** 为准。若工具/审查输出 Critical/Important/Minor，必须映射：`Critical→P0/P1（一票否决）`、`Important→P1（必须清零）`、`Minor→P2/P3（记待办，严禁内耗）`。

---

## 1. 全流程八步（多任务链适用）

| 步 | 动作 | 产物（必须落文件，不靠对话记忆） |
|---|------|-------------------------------|
| 1 | **预检接缝扫描**：开工前扫“任务×共享文件/接口”表，标出每个接缝的生产者→消费者，逐条给裁定 | 写入进度账本 |
| 2 | **任务简报**：每个任务的需求写成独立 brief 文件（精确值、接口签名、验收标准原样在内） | `task-N-brief.md` |
| 3 | **实现**：实现者只读 brief；完成后写**报告文件**（做了什么、测试证据、偏差与顾虑） | `task-N-report.md` |
| 4 | **审查包**：生成 `BASE..HEAD` 的 commit+stat+diff 单文件，审查者只读三件套（brief/报告/diff 包） | `review-*.diff` |
| 5 | **双裁决审查**：必须同时输出 ① 规格符合 ✅/❌ ② 质量 Approved/分级发现；**审查者亲手重跑门禁，禁止只信报告** | 审查结论 |
| 6 | **Fix 循环 ≤5 轮**：R1–R3 唤醒原实现者带发现原文修；R4–R5 换更强模型新人接手；**每轮修完必须做一次范围收窄的复审**；到 5 轮未清 → 上级逐条裁定（修/记档驳回/记待办），禁止无限转 | 逐轮记录 |
| 7 | **阶段终审**：整段 diff 对抗审查 + 把全部延后项做 **a/b/c 三级裁决**（a=合并前必修 b=进待办 c=作废） | 终审报告 |
| 8 | **Rulings 披露 + 交付菜单**：见 §3；随后给出 Merge/Push/Keep 选项由用户拍板 | 用户确认 |

**停止准则不自造**：任何阶段的“能不能收”一律执行 `TESTING.md` DoD——**P0/P1 清零 + 测试 100% 且 `skipped=0` → 必须明确宣布通过，严禁借 P2/P3 理论风险无限发散**。

---

## 2. Carry-forward（审查发现不得蒸发）

- 审查发现但本轮不修的 → **写入进度账本**（分级+一句话），并**原文携带进下一个相关任务的派发指令**；
- 跨阶段的发现 → 升级写入 `ROADMAP.md` 待办行，由终审在阶段收尾**核对原文确实在档**；
- 实现者报告里的“顾虑”与“偏差”必须被审查者逐条裁决（接受/升级/驳回），不许沉默跳过。

---

## 3. Rulings 披露（阶段收尾必做）

当用户授权“自动做完/失败才停”的整段流程时，收尾必须交付**裁定清单**：本阶段 AI 替用户拍板的决定，一行一条，格式 `裁定 → 判错的代价`。
- **收录阈值**：只收改变**行为/范围/代价**的决定；纯实现细节不收。
- **分工**：需要长期留存的按 AGENTS 引擎1.4 写入 `DECISIONS.md`（持久账本）；本清单是**面向用户的阶段汇总**，两者不互相替代。
- **禁止静默裁定**：没有披露的决定视为流程违规。

---

## 4. 进度账本 × 微快照（双轨互补）

- **代码快照**：大重构前 `python scripts/checkpoint.py save "说明"`（AGENTS 引擎“微快照”）——管**代码状态**可回滚；
- **进度账本**：多任务链期间维护一个 `progress.md`（当前任务、已完成行、延后项、裁定）——管**流程状态**，防止长对话失忆重复干活；阶段收尾随工作区清理，承重内容已沉淀进 DECISIONS/ROADMAP。
- 两者不可互替：账本不能回滚代码，快照不记审查结论。

---

## 5. 事故条目（写进 DECISIONS 的格式 + 一个范例）

格式：`症状 → 根因链（几级） → 最小修复 → 如何验证 → 如何防复发`。

> **范例**：CI 发布工作流“启动即死、0 job” → 根因链：secret 存了二进制原文 → GitHub 要求 UTF-8 → 工作流引用即校验失败 → 修复：`base64 < 文件 | gh secret set` 重设 → 验证：重跑 run 出现全部 job → 防复发：模板 README 注明“secret 只存文本（base64），永不存二进制”。

**可选配方（有版本号/状态多处同步的项目才用）**：CI 加一条一致性 grep（pubspec 版本 vs 文档版本不一致即红灯），把“防漂移”从自觉变自动。

---

## 6. 反模式（出现即违规）

| 反模式 | 正解 |
|--------|------|
| 静默替用户做范围级决定 | 进 §3 Rulings 清单 |
| 审查者只读报告不重跑门禁 | 门禁必须亲手再跑一遍 |
| fix 轮超 5 轮仍继续加修补 | 上级逐条裁定，修/驳/记档 |
| 两套严重度阶梯混用 | 以 P0–P3 为准，见 §0 映射 |
| 审查发现“以后再说”却不入账本 | §2 carry-forward |
| 阶段收尾只报“全绿”不报裁定 | §3 强制清单 |
