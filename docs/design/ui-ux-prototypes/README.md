# DaySpark UI Exploration — 三方向对比

日期：2026-10-22  
范围：只做视觉设计。未修改 DaySpark 仓库源码，未实施 Flutter，未开 PR。  
入口：`index.html`（画廊） · `shots/contact-sheet.png`（12 页总览）

## 1. 共同前提

三套原型共用 `assets/data.js`，同一天 `2026-10-22`，同一组代表性数据：

- 重叠事件：11:30–12:30 与设计师午餐 / 12:00–13:00 客户电话·北岸
- 任务安排：晨间回顾、写 v0.29 发布说明、回复客户邮件、整理评审纪要、设计走查准备
- 截止事项：Q4 预算表 18:00、预约牙医、逾期差旅报销
- 重复任务：每日站会记录（第 18 次）、每周复盘、读 20 页《设计中的设计》
- 完成态：3 项已完成；逾期 2 项；今日截止 3 项；收件箱未安排 4 项
- 六件事上限、标签、列表、子任务、备注、负载均在同一数据源中

领域语义按 SPEC 处理：**Event 占时间；TaskAllocation 是可移动的执行安排；Todo.dueDate 是截止，不占时间轴**。三套都用不同的视觉语法表达这三者，而不是只换颜色。

## 2. 三个方向

| | A · Refined Native 精致原生 | B · Precision Workspace 高密度工作空间 | C · DaySpark Signature 品牌签名 |
|---|---|---|---|
| 视觉语言 | iOS 系统色、白 sheet、SF Pro、蓝色主操作、12px 分组卡 | 深色侧栏、冷灰画布、等宽数字、钴蓝、行式 + 检查器 | 暖纸、宋体大数字、柿色/橄榄、24h 光带、编年账本 |
| 信息结构 | 单列优先 + 次级右栏；周视图是日历主态 | 三栏工作台：导航 / 行式时间轴 / 固定检查器；桌面 Todo 为 8 列表格 | 大日期 + 光带 + 账本行；右侧“今日要做”是第二阅读层 |
| 动作入口 | 底部三 tab，Action 为默认 | 底部三 tab；桌面侧栏带快捷键 | 底部三 tab；顶部品牌条 |
| 移动端 | 最接近原生日历；周条 + 分组卡 | 深色 app bar + 紧凑行；指标压成一行后密度可控 | 与桌面同构的编辑版式；日切换、六件事、完成控件已补 |
| 主要优点 | 零学习成本；跨端功能最完整；截止始终单独成组 | 领域模型直接变成视觉语法；负载/缓冲/六件事可扫读；效率工具齐全 | 最强品牌记忆点；日历图例直接写出“占时间 / 可移动 / 不占时间” |
| 主要风险 | 换 logo 可成为任何日历 App；蓝色语义略拥挤 | 高密度对辅助字号和触控目标要求高；固定检查器占宽 | 编辑性装饰挤占首屏；浅灰小字对比度；柿色语义过多 |
| 适合 | 稳妥的跨平台基线 | DaySpark 的差异化主方向 | 品牌层/官网/发布物料，或作为视觉皮肤 |

## 3. 评审结果

两轮隔离评审，互不复用对方结论：

1. **设计评审（Assessment A）**：逐页看 12 张截图，按 Nielsen 十项打分并给 P0–P3。总分 **A 27 / B 32 / C 27**，三套均无 P0；结论是 B 的 IA 最贴 DaySpark，A 最稳，C 品牌最强但移动端功能缺口最大。
2. **证据评审（Assessment B）**：Impeccable detector + 真实浏览器测量。首轮发现 A 日历底部 21:00 线被裁 22px，已在最终版修复；其余为 detector 对“语义色条/占用斜线/暖纸底色”的误报。

评审后做的实际修改：

- **A**：补日历三行图例（事件/安排/截止）；移动端周切换加左右箭头；`GRID_H` 686→662，修复 21:00 不可达；收窄重叠事件标题字号与内边距，减少单字换行。
- **B**：移动端四格指标压成一行，密度条并入日期头部；行高 39→44、标题 12.5px、辅助 9.5–10px、完成框 16px；日期两侧加日切换；密度条补图例；检查器 316→300 并补创建/更新时间；桌面完成框 16px。
- **C**：全局辅助色 `#8c9086`→`#676c62`（纸上对比度约 4.6:1）；移动端标题 13px、辅助 10px、时间 9px；移动端补日切换、六件事入口、明确的方形/圆形完成控件；截止标题由柿色降为墨色，只保留柿色标记；移动端“逐时”统一为“时间轴”；光带补“事件/安排”图例。

## 4. 推荐

**推荐 B · Precision Workspace。**

理由不是“看起来最专业”，而是它是唯一一套让 DaySpark 的产品理由在首屏可见的方向：

- Event / TaskAllocation / deadline 在每一行都有图标、文案、时长和位置差异，不依赖 tooltip。
- “08:30–18:30 已排 4h30m / 可用 6h40m / 68%”把隐藏的排期问题变成可读信息。
- 缓冲冲突用“与上一项重叠”“没有缓冲时间”直接说人话，而不是让用户自己算。
- 六件事是显式的上限入口，不是装饰性 chip。
- 移动端收口后，语义没有丢：仍能看到事件、安排、截止的分组和完成控件。

落地时建议：

- 以 B 为骨架，借 A 的移动端留白和更宽松的触控目标。
- 把 C 的三行日历图例（占时间 / 可移动 / 不占时间）作为 B 的图例文案，而不是只写“事件/安排/截止”。
- 检查器改为“选中后展开、未选中收起”，避免长期占用时间轴宽度；这是 B 目前最大的效率代价。
- 保留 B 的等宽数字和密度条，但把 9px 辅助信息统一抬到 10–11px。

## 5. 已知未完成 / 边界

- 三套都是**静态 HTML/CSS/JS 原型**，没有真实状态管理、拖拽、键盘导航、撤销或空/错/加载态；这些留给 Chat-9 的 Flutter 实现。
- 只做了浅色主题。DESIGN.md 有深色 token，但本轮没有为三套各做深色版。
- 截图是固定视口快照；移动端滚动容器底部存在 5–10px 的尾部留白被裁，属于静态快照限制，不是布局溢出。
- A 的“类别可替换”风险仍在：它最稳，但不像 DaySpark。
- C 的暖纸、宋体、编辑性微排版是刻意选择；Impeccable detector 的 `cream-palette` 警告属于方向本身，不是误装。
- 未做真实设备测试（iOS/Android 实机），未读 Flutter 渲染后的字体度量；原型中的 390×844 只是设计基准。

## 6. 打开方式

```bash
cd docs/design/ui-ux-prototypes   # 从仓库根目录
open index.html
# 或起本地服务，避免个别浏览器对 file:// 字体的限制
python3 -m http.server 8766 --directory docs/design/ui-ux-prototypes
# http://127.0.0.1:8766/index.html
```

直接打开单页：

- `a-refined-native/action.html` / `calendar.html` / `todo.html` / `mobile.html`
- `b-precision/...`
- `c-signature/...`

等待 DaySpark 在线 Chat-8 审定；审定通过后由 Chat-9 进入 Flutter 实施。
