# 与当前 Flutter 的差异清单（供 G2–G6）

基线：`main` @ `46c01fe`，v0.29.0+29。逐条给出「真实代码现状 → 交互模型决定 → 落地成本/风险」，按落地顺序分档。

优先级沿用 P0–P3（P0/P1 阻断，P2/P3 记录）。本清单只描述差异，不改生产代码。

---

## 1. 交互契约级差异（必须先改，否则后续 UI 会在错误前提上叠加）

| # | 真实代码 | 交互模型 | 为什么必须改 | 级别 |
|---|---|---|---|---|
| D1 | 待办/事件详情**内联可编辑**（标题 600ms 防抖直写、截止/优先级/标签/执行时间即刻写） | 详情**只读**；「编辑」进 composer；仅截止/优先级/标签/备注可点开浮层改 | 内联即时写没有提交边界：一次误触即产生一次写入与一次同步，且无法整体撤销。只读详情让「看」与「改」分离，错误可被「取消」拦住 | P0 |
| D2 | 编辑入口分散：详情内联 + `/todo/edit` 表单 + 事件表单编辑分支不可达 | 唯一编辑器 = composer；新建/编辑共用，类型锁定 | 两个编辑器必然漂移（字段校验、重复规则、提醒）。现状已出现漂移：事件日历与提醒只能改表单，而表单编辑路由无调用者 | P0 |
| D3 | 返回/Esc 行为按页不同；Esc 只在两个表单页生效 | 统一：浮层 → 菜单 → 页面自有 escape → 返回 | 现状「Esc 有时关表单、有时什么都不做」，用户无法形成预期 | P1 |
| D4 | 桌面双栏（≥1180）点列表在右栏开详情；搜索结果却整页 push 详情 | 统一单列，返回唯一 | 同一对象两种呈现，返回语义分裂（右栏关闭 vs 页面 pop），是状态泄漏与「选中残留」（G13）的根源 | P1 |
| D5 | 切换 Action/Calendar/Tasks 后右栏仍显示上次选中对象（G13） | 切页清空选中 | 用户以为「回到列表」，实际仍在旧对象上下文 | P1 |
| D6 | 快速添加在 day 视图继承浏览日，Inbox/All 无截止；但无任何提示 | 输入框右侧显示上下文 chip（「11月16日」/「收件箱」） | 现状用户无法判断这条会落到哪一天 | P1 |
| D7 | 无全局捕获入口；Action 不能快速记一条无截止事项 | Action 顶部捕获框 + 底部收件箱入口 | 现状「先记下来」必须走完整表单或切到待办页，丢失了 GTD 式收集 | P1 |
| D8 | 月份视图无任何点击行为（G16） | 点格子下钻到该日 | 现状月视图是「死」的：能看到红点却打不开 | P1 |
| D9 | 删除重复事件的单次实例**无撤销**（G14），而其它删除都有 | 实例删除也给撤销（移除 exdate） | 一致性问题：用户已学会「删除可撤销」，唯一例外会造成数据丢失 | P1 |
| D10 | 取消安排块**无确认**、有撤销；删除待办**有确认**、有撤销 | 取消安排加确认（它会改变日历上的可见计划） | 现状同一类操作确认策略不一致 | P2 |

## 5. 建议的落地顺序（G2–G6）

1. **G2 交互契约**：D1、D2、D3、D4、D5（详情只读 + 单一编辑器 + 统一返回 + 单列 + 切页清选中）。这五项互相关联，必须一起改，否则中间态自相矛盾。
2. **G3 收集与今日**：D7（捕获框）、D6（上下文 chip）、D8（月视图下钻）、N4（节奏条）。
3. **G4 列表操作**：N1（多选）、N2（滑动）、D9（实例删除撤销）、D10（取消安排确认）。
4. **G5 日程与安排**：N6（冲突提示）、N7（类型切换）、N9（详情实例列表）。
5. **G6 状态与一致性**：N8（离线段）、D 系列一致性收尾 + 全部空/错/禁用态按 `BEHAVIORS.md` 对齐。
