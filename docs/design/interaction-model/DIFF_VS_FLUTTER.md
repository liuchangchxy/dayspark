# 与当前 Flutter 的差异清单（供 G2–G6）

基线：`main` @ `7390987`，v0.34.0+34（`feat(ux): whole-product UX convergence`）。

上一版本文档基于 `46c01fe`（v0.29.0+29），落后 55 个提交。v0.34.0 已把 Core UX 冻结成 `docs/CORE_UX_SPEC.md`，并在真实代码里落地了一部分交互契约，因此**本清单逐条对着 7390987 重新核验过**：有 5 条（D2/D4/D5/D8/D13）已在真实代码中修复，降级为「已一致」；术语也按冻结规范更新。

优先级沿用 P0–P3。本清单只描述差异，不改生产代码。

## 5. 建议的落地顺序（G2–G6）

1. **G2 交互契约**：D1（详情只读）、D3（统一返回，含菜单 Esc 顺序）、D14（补回规范要求的桌面侧栏）、D23（系列不整体完成）。master-detail 真实代码已实现，按 §1.1 验收即可。

5. **G6 状态与一致性**：N8（离线段）+ 全部空/错/禁用态按 `BEHAVIORS.md` 对齐。

| I3 | 设置的数据区以 .ics 为主，备份与合并备份没有独立行 | 数据区：导出 .ics / 导出全部日历 / 导出完整备份 / 合并备份 / 标签(计数) / 回收站(计数)（D-19） | 备份是完整可恢复的 JSON，合并按 id + `updatedAt`，且必须**报告新增/更新/跳过**；不得把合并叫成导入替换 |
| I4 | 待办日视图按记录类型分组 | 按承诺排序：计划块 → 截止泳道 → 日程 → 已完成（D-17），排序只有一处实现 | 日视图不得把截止当时间块，也不得让日程排在一长串截止之后 |
| I5 | 完成入口分散（列表/详情/今天各写各的） | 全部走 `todo-ops.complete()`，批量完成跳过已完成的 | 生产也只能有一个完成写点；批量不得把已完成实例翻回未完成 |
| I6 | 重复待办的安排不绑定实例，移动计划日不重推导 occurrence | `syncOccurrence` 在保存与落位时都重推 occurrence；无实例则不写 | 任何改变「哪一天」的写入（表单、拖动、改期）都必须重推 `occurrenceId` |
| I7 | 新建日程默认落在被折叠的凌晨时可能不可见 | 默认开始时间不早于 08:00（当天与将来一致） | 新建对象的默认落点必须落在用户可见区间；折叠区不是默认落点 |
| I8 | 种子/演示数据只有中文，切换语言后仍是中文 | `localizeSeed()` 只在值仍等于任一语言变体时替换 | 演示数据不是用户数据，切语言必须跟着走；用户改过的字段不得被覆盖 |
