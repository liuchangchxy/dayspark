基线：`main` @ `7390987`，v0.34.0+34（`feat(ux): whole-product UX convergence`）。

### 1.1 桌面 master-detail —— 已按冻结规范落地

`CORE_UX_SPEC.md` §4 规定桌面 master-detail，真实 v0.34.0 也已实现。原型此前把它记成「有意不做」，是判断错误：规范是冻结的，不能用「返回语义会分裂」这个偏好推翻。

现状：≥1180 时待办页左侧列表常驻、右侧详情窗格；点别的行替换窗格；有可见关闭；`Esc` 先关窗格；切目的地清选中；手机仍是整页详情。**不再是待决项。** 验证见 `tests/reviewer-findings-r3.js` P1-6 与 `tests/reviewer-findings-r4.js` D3/D10/D11/D17。

## 5. 建议的落地顺序（G2–G6）

1. **G2 交互契约**：D1（详情只读）、D3（统一返回，含菜单 Esc 顺序）、D14（补回规范要求的桌面侧栏）、D23（系列不整体完成）。master-detail 真实代码已实现，按 §1.1 验收即可。
2. **G3 收集与今日**：D7（今天页捕获框）、D6（上下文 chip）、N4（节奏条）。
3. **G4 列表操作**：N1（多选）、N2（滑动）、D9（实例删除撤销）、D10（取消安排确认）。
4. **G5 日程与安排**：D11（删除作用域收敛）、D12（实例编辑基准日）、N6、N7、N9。
5. **G6 状态与一致性**：N8（离线段）+ 全部空/错/禁用态按 `BEHAVIORS.md` 对齐。
