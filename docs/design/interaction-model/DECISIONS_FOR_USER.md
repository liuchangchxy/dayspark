`CORE_UX_SPEC.md` §4 明确规定桌面 master-detail，真实 v0.34.0 也已实现。我原先把这条记成「有意不做」，是我判断错误——规范是冻结的，不该由我用「返回语义会分裂」这个理由推翻。

现已实现为**选中而非路由**：≥1180 时待办页左侧列表常驻、右侧详情窗格；点别的行替换窗格；有可见「关闭」；`Esc` 先关窗格再谈离开；切目的地清选中；手机仍是整页详情。两端能力相同、外壳不同。

**不需要你再决定。** 依据 `CORE_UX_SPEC.md` §4 / §12，验证见 `reviewer-findings-r3.js` P1-6。

## 2. 月视图里能否直接新建（当前原型：桌面双击空格子新建；手机点有事项的日期下钻）

- **A（推荐，已实现）**：手机点格子 → 有事项才下钻 → 点时段新建；桌面双击空格子 → 在下一个整点新建日程。与 v0.34.0 一致，误触率低。
- **B**：手机点格子也直接弹「新建日程 / 安排待办」。少一步，但月格 90×90 里的弹层选择容易误触。

**现状已是 A，不需要你再选**；保留此条仅用于说明取舍。

## 3. 手机月视图的信息密度（当前原型：彩色圆点 + 「+n」）

手机月格宽度放不下「11:30 与设计师午餐」。当前做法是圆点表示有事项，点格进当天看详情。

- **A（推荐）**：圆点 + 计数，靠下钻看内容。
- **B**：保留文字 chip，允许截断（现状截成「11:3…」，几乎不可读）。

---

## 4. 安排冲突：允许并警告，还是阻止保存（当前原型：允许 + 警告）

- **A（推荐）**：保存成功，toast 警告「与 X 冲突」。与真实代码「手动排程不校验」一致；不阻断用户。
- **B**：直接禁用保存直到不重叠。更严格，但会把「我就想同时排两件」的用户挡在门外。

---

## 5. 删除/取消类操作是否统一加确认（当前原型：删除有确认 + 撤销；取消安排有确认 + 撤销）

现状 Flutter 不一致（删除有确认、取消安排无确认；单次实例删除还**没有撤销**，见 `DIFF_VS_FLUTTER.md` D9）。

- **A（推荐）**：统一为「破坏性操作 = 确认 + 撤销」。
- **B**：只保留撤销（toast 5 秒），不加确认，少一次点击。风险是误触后若没看见 toast 就丢了。

---

## 6. 重复日程删除：给两个还是三个范围（当前原型：三个）

真实代码的详情页问「仅此次 / 整个系列」两个选项。原型统一为三个：**这一次 / 以后 / 整个系列**（与拖动、编辑同一套话术）。

- **A（推荐）**：三个。用户说「以后都改到 10 点」是最常见的需求，缺了它只能逐次改。
- **B**：两个，与真实代码一致，实现更简单，但「以后」只能靠编辑系列绕。

---

## 7. 中途完成的待办，它正在进行的安排算什么（当前原型：算历史，立刻离开「现在」）

15:30–16:10 有安排，15:45 勾选完成。

- **A（推荐）**：立刻离开「现在」，进入「今天早些时候」；日历不再把它画成当前工作，记录保留为历史。与 `isAllocationLive` 已有的「完成时刻之后的安排失效」规则同源。
- **B**：留在「现在」直到时段结束，只是打个勾。更符合「我还在做这件事」的直觉，但会和「今天早些时候」重复计数。
