# 需要你拍板的分歧 / Decisions that need your call

按 G0 的要求：不把产品分歧逐条丢给你回答；先各自做出可运行版本、给出推荐，只在最后集中列出**真正需要你选**的几条。其余决定已落在原型里，理由见 `COVERAGE.md` §7 与 `DIFF_VS_FLUTTER.md`。

## 1. 桌面是否要「左列表 + 右详情」双栏（当前原型：不做）

| | 方案 A：统一单列（原型现状，推荐） | 方案 B：≥1180 双栏 |
|---|---|---|
| 返回语义 | 唯一：返回 = 回到上一页 | 两种：关右栏 / 页面返回 |
| 与「详情只读、编辑显式」的关系 | 一致：详情是一页，看完就退 | 冲突：右栏要常驻「当前选中」，选中状态成为第二套导航 |
| 现状 Flutter 的问题 | — | 切 tab 后右栏仍显示旧对象（G13 状态泄漏），搜索结果却是整页 push |
| 代价 | 桌面宽屏右侧留白 | 需要额外定义「选中 ≠ 导航」并清理残留 |

**推荐 A**。若你选 B，G2 需要先定义选中与返回的分离规则，再实现。

## 2. 月视图里能否直接新建（当前原型：不做，点格子先下钻到当天）

- **A（推荐）**：点格子 → 日视图 → 点时段新建。误触率低，且月格尺寸放不下时段选择。
- **B**：点格子直接弹「新建日程 / 安排待办」。少一步，但月格 90×90 里的弹层选择容易误触，且「点哪天」与「建在哪天」混为一谈。

---

## 3. 手机月视图的信息密度（当前原型：彩色圆点 + 「+n」）

手机月格宽度放不下「11:30 与设计师午餐」。当前做法是圆点表示有事项，点格进当天看详情。

- **A（推荐）**：圆点 + 计数，靠下钻看内容。
- **B**：保留文字 chip，允许截断（现状截成「11:3…」，几乎不可读）。

---

## 4. 安排冲突：允许并警告，还是阻止保存（当前原型：允许 + 警告）

- **A（推荐）**：保存成功，toast 警告「与 X 冲突」。与真实代码「手动排程不校验」一致，AI/MCP 才校验；不阻断用户。
- **B**：直接禁用保存直到不重叠。更严格，但会把「我就想同时排两件」的用户挡在门外。

---

## 5. 删除/取消类操作是否统一加确认（当前原型：删除有确认 + 撤销；取消安排有确认 + 撤销）

现状 Flutter 不一致（删除有确认、取消安排无确认）。原型统一为「破坏性操作 = 确认 + 撤销」。

- **A（推荐）**：统一。
- **B**：只保留撤销（toast 5 秒），不加确认，少一次点击。风险是误触后若没看见 toast 就丢了。

---

## 6. 附件、ICS、同步、AI 在本轮只定义「界面行为」

原型里这些是模拟延迟 + 结果 toast（`DIFF_VS_FLUTTER.md` §4 S1–S4）。需要你确认：G2 是否接受「交互先定稿、真实上传/解析/同步随后补」，还是必须在本轮就把真实链路一起定义。
