# 全产品覆盖表 / Full-product coverage table

把 `research/APP_SURFACE.md`（真实 Flutter 代码盘点，973 行）中的每一处用户可达界面、入口、菜单、弹层与操作，映射到原型的路径与控件，并标注本轮的**设计决定**：沿用 / 重做 / 新增 / 有意不做。

- 原型入口：`docs/design/interaction-model/index.html`（直接双击，或 `python3 -m http.server` 后访问）
- 状态列含义：
  - **同** = 与当前 Flutter 行为一致，原型照做
  - **改** = 保留功能，交互方式重新设计（差异清单 §1 有逐条说明）
  - **新** = 当前 Flutter 缺失或不可达，原型补上（差异清单 §2）
  - **不做** = 明确决定不在本轮交互模型内（含理由）
- 覆盖统计：APP_SURFACE 列出的 **31 个界面区域 / 24 条路由入口 / 6 类创建流 / 8 类编辑面 / 9 类手势 / 21 项破坏性操作 / 15 组设置 / 5 类状态**，全部有归属；**无一条“未处理”**。

## 7. 明确不做 / 留待 G2–G6 的项（附理由）

| 项 | 理由 |
|---|---|
| ~~桌面 master-detail 双栏~~ | **已按规范落地，不再是不做项。** 我最初以「返回语义会分裂」为由做成单列，这个理由权重不够：规范是冻结的，真实 v0.34.0 也已实现。现已实现为「选中而非路由」——列表常驻、窗格可关、Esc 先关窗格、切目的地清选中。见 `COVERAGE.md` §1 第 22 行与 `BEHAVIORS.md` A6。 |
| 手机月视图内直接创建 | 手机月格尺寸不足以容纳创建手势：点有事项的格子下钻，空格不动作。**桌面已支持双击空格子在下一个整点新建日程**（与 v0.34.0 一致）。 |
| widget 深链 `dayspark://quick-add` | 链接本身属平台集成；其**目的地** `/quick-add` 已作为应用内「快速添加」页实现（rail / 手机更多 / Q）。深链唤起仍未建模。 |
| legacy 重复规则确认流程 | 需要真实历史数据才能演示，原型不含 legacy 记录；已在 `DOMAIN_BEHAVIORS.md` §5 记录契约，留给 G2。 |
| 附件真实上传 / ICS 真实解析 / 真实同步 | 原型用模拟延迟与结果 toast 表达状态；真实实现属 G2–G6。 |
| 通知本体点按导航、Snooze 持久化 | 平台通道无法在网页原型里真实存在。已在「状态与边界」用模拟通知卡定义两个操作的行为（完成 / 稍后 10 分钟）；持久化留给 G2。 |
| ~~清空 AI 对话按钮~~ | **已实现**：会话非空时页头出现清空按钮，二次确认后清空消息（已创建的事项不受影响）。 |

### 8.6 审计中「原型有、真实没有」的项

rail、行菜单、多选、拖动排序、滑动、块改尺寸、今天节奏条等，都是 G0 的**交互提案**，不是覆盖率。与冻结规范冲突或明显无用的项已删：搜索范围（真实代码不分范围）、六件事、每周起始日；农历开关保留为外观示例。它们不能算作「已覆盖真实功能」，已在差异清单里标明。

### 8.7 结论

审计列出的 24 项缺失中，除平台集成（深链、Android 返回、Web URL、通知持久化）与 legacy 数据外，均已在原型中有可操作路径；61 项「部分」按上表补到行为可操作，形状差异保留为设计决定。**没有把未实现项标成通过。**
