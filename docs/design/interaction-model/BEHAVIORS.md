# 关键操作行为定义 / Key-operation behaviour contract

每条操作写清三件事：**数据怎么变 → 界面怎么回 → 失败怎么办**。原型代码即实现，测试即证据（`tests/*.js` 的场景名对应下表编号）。

术语与规则以 `docs/CORE_UX_SPEC.md`（v0.34.0 冻结）为准：**今天 / 未安排 / 全部待办 / 计划执行 / 截止**。领域语义遵循 `SPEC.md`：`dueDate` 是截止（不是执行时间）、`TaskAllocation` 是可移动的执行时段、`Event` 占据时间。三者永不互相冒充。

---

## A. 全局


### A1 创建入口（唯一入口原则）
- **数据**：`composer` 路由，`kind` 在打开时确定；新建待办默认**无截止**、第一个日历、优先级 0；新建日程默认「今天下一个整点 + 1 小时」。
- **界面**：桌面与移动都从页头「新建」（不设 FAB）；日历从时间格 sheet；一句话创建走「快速添加」页。**「新建」打开的是二选一 chooser（待办 / 日程），不是直接跳表单** —— 见 A5。保存后**回到打开它的地方**并按 `{testid, id}` 高亮**那一行**（不是第一行）。子任务例外：回父详情。
- **失败**：标题为空 → 保存禁用 + 内联错误，不写库。脏表单离开 → 先确认「放弃修改？」——**Esc、侧栏、底部导航、快捷键全部走同一问句**（`App.leaveGuard`），不允许静默丢弃草稿。
- 证据：`interactions.js`「composer creates a todo…」「composer blocks saving an empty title…」「leaving a dirty composer…」；`reviewer-findings.js` F8 / F19

### A2 返回语义（唯一返回路径）
- **数据**：`history` 栈；`back()` 弹一层。
- **界面**：`Esc` 先关最上层浮层（sheet/modal/menu）→ 再关菜单 → 再交给页面自己的 escape 处理（composer 会先问是否放弃）→ 最后才返回上一页。`action` 是根，不返回。
- **失败**：无历史 → 回 `action`。
- 证据：`interactions.js`「Escape closes the top overlay first…」

### A3 页面切换清理
- **数据**：`navigate/back` 一律关闭全部 sheet/modal/menu 与 toast。
- **界面**：不残留遮罩、不残留可点击但看不见的层。**有浮层时全局快捷键（N / / / T / ?）全部失效**，不会把底下的页面改掉。
- **失败**：无。
- 证据：`surfaces.js` 全套（切换页面后仍可点击）；`reviewer-findings.js` F18。

### A4 今日 vs 浏览日
- **数据**：今天页每次渲染都按钟取 `startOfDay(now)`（跨午夜自动翻页）；`todosView.day` 只由周条/日历下钻写。两者独立。
- **界面**：今天永远显示今天，页头无日期切换；待办页周条可看任意日，页头副标题显示所看日期（跨年时带年份）。
- **失败**：无。
- 证据：`interactions.js`「browsing another day in Todos does not move the Action day」

### A5 今天页的创建（不得编造截止）
- **数据**：`openCreateChooser()` 只负责选类型，**不写任何字段**。选「待办」→ composer 无 `dueDate`，保存后落到「未安排」；选「日程」→ composer 预填今天下一个整点。
- **界面**：sheet 两个出口，各带一行说明（「无截止，落到「未安排」」/「今天下一个整点」）。
- **失败**：没有第二条入口在背后偷偷写 `dueDate = 今天`——**在哪个页面打开都不等于给截止**。
- 依据：`CORE_UX_SPEC.md` §3.1 / §3.2
- 证据：`reviewer-findings-r2.js` R12；`interactions.js` 捕获链路

### A6 桌面 master-detail（选中 ≠ 路由）
- **数据**：`paneSelection = {type, id, occurrence}`。**写入选出不进历史栈**；关闭只清选中。
- **界面**：宽度 ≥1180 且在**待办**目的地时，左侧列表常驻、右侧详情为窗格。点另一行替换窗格内容；窗格有可见的「关闭」；`Esc` **先关窗格**（不离开页面）；切换目的地（今天/日历/待办以外的页）清空选中；选中行在列表里高亮。
- **失败**：**手机端不渲染窗格**，走整页详情 + 返回，两端能力相同、外壳不同。从搜索/日历打开记录仍是整页，不会被劫持成窗格。
- 依据：`CORE_UX_SPEC.md` §4 / §12（「Desktop master-detail keeps the list visible」）
- 证据：`reviewer-findings-r3.js` P1-6 / P1-6b

### A7 一个浏览日（浏览 ≠ 今天）
- **数据**：`browseDate` 是待办「按日期」与日历共用的唯一浏览日。待办选日、日历点日、日历翻页都写它；「回到今天」也写它。
- **界面**：切换 tab 不改 `browseDate`。
- **失败**：**今天页永远读时钟**，任何浏览都不会把它移到别的日期。
- 依据：`CORE_UX_SPEC.md` §16.1
- 证据：`reviewer-findings-r3.js` P1-8


### A8 快速添加（一句话创建）
- **数据**：规则：带时刻 → Event（默认 1 小时，可带「N 小时/分钟」）；只有日期 → Todo 截止（日期型，无 00:00）；什么都没有 → 无截止 Todo。**保存前不写任何东西**。
- **界面**：入口为 rail「快速添加」、手机「更多」、快捷键 `Q`。预览卡先说明「将创建日程 / 待办」、标题、时间；手机另有「保存并再加一条」。类型可手动覆盖（自动 / 日程 / 待办），覆盖后预览同步改口。
- **失败**：识别不出日期 → 仍按无截止待办创建，并在预览里明说；空输入 → 保存禁用。
- 证据：`reviewer-findings-r4.js` D18；`interactions.js` 创建链路

### A16 实例的时间是它的开始时间
- **数据**：`occurrenceAnchor` 只是用于从系列中排除该实例的午夜键，绝不作为实例开始时间传给详情或编辑器。
- **界面**：从今天、日历、搜索打开同一个重复日程，详情与编辑时间一致。
- **失败**：无。
- 证据：`reviewer-findings-r8.js` R8-1。

### A17 逾期按日判断
- **数据**：`逾期` = 截止日 < 今天。日期型截止在当天不算逾期；只有当天过去才进入逾期区。
- **界面**：今天截止的行不画逾期底色、不写逾期；日历泳道日期不标红。
- **失败**：无。
- 证据：`reviewer-findings-r8.js` R8-2。

### A18 触摸拖动必须真正生效
- **数据**：日历块、缩放手柄、排序抓手声明 `touch-action:none`；`pointercancel` 只中止、不提交。
- **界面**：手机上一个真实触摸拖动会移动块，长按抓手会改顺序；被系统打断时什么都不改。
- **失败**：无。
- 证据：`reviewer-findings-r8.js` R8-5（CDP 真实 touch）、R7-6、R6-5。

### A14 编辑草稿不引用 store 对象
- **数据**：composer 草稿里的所有 Date 都是副本；切全天/改时间只动草稿，取消后原记录不变。
- **界面**：取消编辑不产生任何写入或副作用。
- **失败**：无。
- 证据：`reviewer-findings-r7.js` R7-2。

### A15 每个目的地有自己的滚动位置
- **数据**：滚动位置按路由 key 保存，离开时记录、回来时恢复；新目的地从顶部开始。
- **界面**：长列表选中记录或从今天返回时不会被送回顶部。
- **失败**：无。
- 证据：`reviewer-findings-r7.js` R7-5。

### A12 页面上下文跨重绘保留
- **数据**：设置分区写 `state.settingsSection`；滚动位置在每次渲染前按容器快照、渲染后恢复。
- **界面**：切换 AI/登录/完成记录/拖动块都不把用户送回页面顶部或别的分区。
- **失败**：无。
- 证据：`reviewer-findings-r6.js` R6-1、R6-2。

### A13 英文快速添加
- **数据**：英文日期（today/tomorrow/next Monday/月份名/ISO）、时刻（3pm/15:00/at 3）、时长（for 1 hour）与中文同规则：有时刻→日程，只有日期→截止，都没有→无截止待办。
- **界面**：预览先说明将创建什么；标题去掉日期时间词。
- **失败**：无法解析时明确说「没有识别到日期」。
- 证据：`reviewer-findings-r6.js` R6-16。

### A10 Quick Create（新建待办的第一形态）
- **数据**：新建 Todo 默认 `quick=true`；只渲染标题、截止、所属日历（仅多日历）、更多；「更多」把同一份草稿展开成完整五段，不新建第二份草稿。
- **界面**：编辑既有记录、新建日程仍直接是完整表单；类型切换保留。
- **失败**：无。
- 证据：`reviewer-findings-r5.js`「P2-11」。

### A11 重复待办的执行时间必须落在实例上
- **数据**：给重复待办安排时间时，从计划时间所在日解析 `occurrenceId`；当天不匹配规则则校验阻止保存并保留草稿；AI/聊天路径找最近匹配的发生日，找不到就拒绝写入。
- **界面**：保存标签只在确实会写入时列出执行时间；toast 明说排到了哪个发生日。
- **失败**：没有发生日 → 不写 `occurrenceId=null`，不报「已应用」。
- 证据：`reviewer-findings-r5.js` P1-7、P2-1。

### A9 草稿必须跨重绘存在
- **数据**：编辑中的草稿存在 `state.composerDraft`，以路由参数为键；脏标记写在草稿上。
- **界面**：跨断点缩放、主题/语言切换、打开日历创建/AI 解析等任何重绘，标题、备注、截止、时段都不丢；关闭时仍然问「放弃修改？」。
- **失败**：保存或真正离开后清空草稿；同一个空白新建入口不会复用上一次的草稿。
- 证据：`reviewer-findings-r4.js` D1 / D2

## B. 待办

### B1 捕获（今天页捕获框）
- **数据**：`createTodo({summary})` → 无 `dueDate`、无 `startDate`、`status=NEEDS-ACTION`、`parentId=null`、无重复。即「未安排」。
- **界面**：输入框清空、**焦点留在框内**（连续输入可直接建第二条）；「未安排」计数 +1，**刚建的那条出现在今天页的未安排预览里并高亮**（预览最多 3 行，新条目在超出时提到首位，否则用户看不到自己刚建的东西）；toast「已创建 …」带撤销。
- **失败**：空输入 Enter 无效。
- 证据：`interactions.js`「action capture creates an unplanned todo…」；`reviewer-findings-r2.js` R12

### B2 快速添加（待办页）
- **数据**：day 视图 → `dueDate = 该日 00:00`（日期型，不显示 00:00）；未安排/全部待办 → `dueDate = null`。
- **界面**：新行出现在对应分区；输入框清空并保持焦点。
- **失败**：空输入无效。
- 证据：「todos quick add inherits the browsed day as deadline」

### B15 取消的排序/拖动不提交
- **数据**：`pointercancel`（被系统滚动/来电打断）只清理视觉，不改顺序、不写时间、不提示成功。
- **界面**：排序抓手下一次点击仍正常。
- **失败**：无。
- 证据：`reviewer-findings-r7.js` R7-6；`reviewer-findings-r6.js` R6-5。

### B3 完成 / 取消完成
- **数据**（非重复）：`status: NEEDS-ACTION → COMPLETED`，`completedAt = now`；**所有 `startAt >= completedAt` 的 active 安排 → `invalidatedByCompletion`**；早于完成时刻的安排保留为历史。
- **数据**（撤销完成）：状态回退、`completedAt = null`，并**把这次完成作废的安排改回 `active`**——否则待办回来了、它占的时段却永久消失，界面上没有任何地方说明它去了哪。只恢复「被这次完成作废」的那些（`startAt >= 该次完成时刻`），用户自己取消过的安排不复活。
- **数据**（重复）：只写 `occurrenceStates[occId].completedAt`，**系列本身永远保持 NEEDS-ACTION**；同样使该实例未来的安排失效；撤销时把该实例被作废的安排改回 `active`。
- **界面**：行移到「已完成」区（Day 单区 / 全部待办·未安排按完成日分组）；今天页出现于「今天早些时候」，**并立即离开「现在 / 接下来」**；日历不再把该安排画成当前工作（记录保留为历史）；toast 带撤销（撤销 = 再调一次 `completeTodo`，即反操作）。**日视图的「计划执行」段不再渲染已完成的待办**——已开始的安排按 INV-144 保留为 active，并在日历上画成历史块（灰调、虚线边框、无拉伸/拖动/右键菜单，点开记录；月份格计入该条），裁定 D-11 / D-28。
- **实现**：所有入口（列表勾选、详情按钮、今天行）共用 `js/todo-ops.js` 的 `complete()`。**批量完成前先判断是否已完成**，已完成的计入跳过，绝不把已完成的实例切换回未完成。
- **失败**：重复待办且今天没有匹配实例 → 警告 toast，不写库；**绝不出现「没写库却报已完成」**。
- 证据：「completing a todo moves it to the completed section…」「completing one occurrence of a recurring todo…」；`reviewer-findings.js` F3 / F11；`reviewer-findings-r3.js` P1-1 / P1-1b / P1-2

### B4 删除 / 恢复 / 永久删除
- **数据**：删除 = `deletedAt = now`（软删），父子任务在同一时刻级联软删。恢复 = `deletedAt = null`（保留截止、标签、安排等全部字段），**恢复父任务会把同一时刻级联删除的子任务一并恢复**；单独删过的子任务保持自己的删除时刻，不随之复活。永久删除 = 整棵子树移除（含已软删的孙级）+ 其安排一并移除。
- **界面**：行菜单 / 滑动 / 详情 / 批量都先问一次（裁定 D-10：一次确认 + 撤销，不是二选一），确认后行立即从列表消失；toast 撤销；回收站出现该行（含删除时间）；恢复后回到原列表；永久删除有二次确认且不可撤销。
- **失败**：恢复一个**父任务已被永久删除**的孤儿子任务 → 拒绝并警告「父任务已不存在」，**不谎报恢复成功**。原日历已被删除时，恢复会把记录重绑到现存第一个日历（裁定 D-21）——恢复不得交回一条界面无法描述的记录。
- 证据：「deleting a todo moves it to Trash…」「trash purge is permanent…」；`reviewer-findings-r2.js` R1

### B5 安排执行时间（不改截止）
- **数据**：新增 `TaskAllocation{todoId, startAt, endAt, state:active, occurrenceId?}`。**`dueDate` 不变，也不创建 Event**。
- **界面**：待办行 meta 出现时间区间；详情「执行时间」事实出现；日历出现虚线安排块；toast 带撤销（撤销 = 取消该安排）。
- **取消**：详情页每条生效安排都有「取消安排」（手机与桌面同一路径，不依赖右键菜单）；取消后块消失、进「历史安排」，可撤销。
- **失败**：与已有安排/事件重叠 → 保存仍允许（手动排程不校验空闲），但 toast 追加「与 X 重叠」；重复待办**必须先选实例**（composer 的排程面板有实例下拉），未选不写库并说明原因。
- 证据：「scheduling a todo from a slot creates an allocation…」「a scheduled todo shows its allocated time…」；`reviewer-findings.js` F4 / F6 / F14

### B6 改期 / 取消安排
- **数据**：改期 = 改写 `startAt/endAt`；取消 = `state = cancelledByUser`（行保留，历史可见）。
- **界面**：块移动位置；取消后块消失、详情「历史安排」出现该条；toast 撤销。撤销**写回改动前的时间**（不是把已改的值再存一遍）。
- **失败**：结束 ≤ 开始 → 内联错误，不写库。
- 证据：「scheduling a todo… can be rescheduled」「cancelling a scheduled block removes the block but keeps the to-do」；`reviewer-findings.js` F7

### B7 详情只读 + 显式编辑
- **数据**：详情不写任何字段；只有点「编辑」进 composer 才写。内联可改的仅：截止、优先级、标签、备注（点值即开编辑浮层，保存即写）。
- **界面**：详情是事实清单（截止/执行/重复/优先级/标签/日历/提醒/父任务/实例/子任务/历史安排/备注/时间戳），底部「编辑」「移到回收站」。**截止/执行/优先级/标签的值本身可点**（`role=button` + Enter/Space），不只是旁边的铅笔。
- **失败**：改完即 toast「已更新」；无撤销（可再改回）。
- 证据：「todo detail is read-only until Edit…」

### B8 子任务
- **数据**：`parentId = 父 id`；子任务不出现在顶层列表、不计入「未安排」、不计入今天页任何分区。
- **界面**：父详情列出子任务，可勾选、可点进；保存后回父详情。
- **失败**：标题为空不保存。
- 证据：「adding a subtask from a parent detail…」

### B9 排序
- **数据**：拖动后按可见顺序重写 `sortOrder = (i+1)*10`。
- **界面**：行立即换位；toast「顺序已保存」。
- **失败**：无。
- 证据：`surfaces.js`「desktop: dragging by the grip handle…」

### B10 多选批量
- **数据**：批量完成 = 逐条 `completeTodo`；批量删除 = 逐条软删（一次确认）。
- **界面**：选择条显示「已选 n 项」+ 全选/完成/删除/取消；操作后退出选择态；删除可撤销。
- **失败**：未选时完成/删除按钮禁用。
- 证据：「selection mode can complete several rows…」

### B11 左滑 / 右滑（触摸端）
- **数据**：左滑超阈值 = 软删；右滑 = 完成。
- **界面**：滑动露出背景提示（完成 / 删除），释放后问一次再执行（裁定 D-10），取消则行弹回原位；删除有 toast 撤销。
- **失败**：滑动不足阈值 → 回弹，不执行。
- 证据：「mobile: swiping a row left deletes it with an undo path」

### B13 计划这一天
- **数据**：打开 composer，`planDate = 所看日期`，预填该日 09:00–10:00 的**计划执行**；**截止保持为空**（计划不是截止）。
- **界面**：日视图输入框下方一条 `计划这一天`；保存后回到该日列表并高亮新行。

## C. 日程（Event）

### C1 创建
- **数据**：`Event{summary, startDt, endDt, isAllDay, calendarId, location?, rrule?, tagIds, reminderOffsets}`。全天事件归零到 00:00–23:59。
- **界面**：时间格出现实心块；Action 对应时段出现；toast 撤销（撤销 = 软删）。
- **失败**：结束 ≤ 开始 → 内联错误 + 保存禁用。
- 证据：「creating an event from a calendar slot…」

### C2 拖动 / 改时长
- **数据**：拖动 = 改 `startDt/endDt`（保持时长，可跨日）；改尺寸 = **只改 `endDt`**（起点不动）；15 分钟吸附。
- **界面**：块跟随移动，释放后落位；拖动与改尺寸**都给 toast**（改尺寸不再静默）并带撤销。
- **手机短块（裁定 D-16 / D-24）**：块高 < 96px 时**不显示缩放条**——缩放条被压到 16px 会既违反 48px 触摸目标、又和拖动抢手势。这些块仍可拖动，改时长走块菜单「改期…」（同时给开始与结束）。块菜单在触摸端由**按住约 480ms** 打开（移动超过 8px 转为拖动），不依赖系统合成右键。≥96px 的块保留 48px 缩放条（拖动区仍占块高一半）。桌面端不受此限，任何高度的块都有缩放条。
- **同槽重叠（裁定 D-25）**：开始/结束完全相同的两个块各占一列、各自可点，不允许一个盖住另一个。
- **撤销**：撤销是**真实逆操作**，不是重绘 —— 普通日程还原拖动前的 `startDt/endDt`；重复实例按所选范围分别还原（删副本 + 移除 exdate / 还原原系列 `until` / 平移回原位）。
- **失败**：重复事件的单次拖动 → 先问「这一次 / 以后 / 整个系列」；选「这一次」= 加 exdate + 建一次性事件。取消 sheet 不写任何数据，块弹回原位。
- 证据：`interactions.js`「dragging an event block moves it and the toast undo puts it back」「dragging one occurrence of a repeating event asks the scope, and undo reverses it」；`reviewer-findings-r9.js` R9-6（短块无 <48px 缩放条，改期仍可达）；重复作用域见 C4。

### C3 删除
- **数据**：单次日程 = 软删；**实例或系列 = 先问范围**：「这一次」→ 加 exdate，系列存活；「以后」→ 系列 `until = 前一天`；「整个系列」→ 软删。
- **界面**：块消失；toast 撤销（实例撤销 = 移除 exdate / 还原 `until` / 恢复软删）。删除后**不停留在已删除记录上**——当前若是详情则返回上一页。
- **实现**：块菜单、右键、详情页三处共用 `js/event-ops.js`，不存在第二套删除逻辑。
- **失败**：取消确认 → 不写；取消范围 sheet → 不写。
- 证据：`interactions.js` 删除路径 + 回收站恢复；`reviewer-findings.js` F1 / F10。

### C5 重复日程的创建
- **数据**：日程表单的「重复」写入 `rrule`；编辑整个系列显示原规则，编辑单个实例不显示系列规则。
- **界面**：重复行在日程的「时间」区，与待办同位置。
- **失败**：无。
- 证据：`reviewer-findings-r6.js` R6-17。

### C4 重复作用域
- **数据**（编辑）：「这一次」→ `exdates += anchor` + 新建一次性事件（`splitEventOccurrence`）；「整个系列」→ 改原系列。
- **数据**（拖动）：「这一次」→ exdate + 一次性副本；「以后」→ 原系列 `until = 前一天`，另起新系列；「整个系列」→ 平移原系列。
- **界面**：先弹作用域 sheet，选择后才写。实例详情显示**实例自己的开始时间**，不是系列基准日，也不是 00:00。
- **失败**：取消 sheet → 不写，块弹回原位。
- 证据：`interactions.js`「dragging one occurrence…」；`reviewer-findings.js` F2。

## G. AI 助手

- **数据**：**提案不写入**。用户点「应用」才执行 `run()`；拒绝则只标状态。会话仅内存。
- **界面**：助手回复 + 提案卡（应用/拒绝）；应用后卡片显示「已应用」且按钮消失，状态跨重渲染保持。最新一条回复下方有四个后续动作：加为日程 / 加为待办 / 安排执行（选待办+时间）/ 拆成子任务（可勾选后创建）。页头在会话非空时提供「清空对话」+ 确认。
- **失败**：无 Key → 空态 + 「配置 AI」；发送中 → 输入禁用、显示输入中气泡；没有可安排待办 → 明确说明。
- 证据：「an AI proposal does not change data until the user applies it」

## H. 异常与缺失记录

- **数据**：不写任何字段。
- **界面（回收站中的记录，裁定 D-18）**：打开**已软删**的 Todo 或 Event → 正常详情，只读，顶部横幅「此记录在回收站」+ 一个主操作「恢复」。恢复后横幅消失、编辑/安排/完成恢复可用。**不能**把可恢复的记录说成"不存在"。只读是整页的：头部菜单不出现、重复实例勾选禁用、所属日历/截止不提供内联编辑、加子任务与删除都不提供。回收站行本身可点开这张只读详情。

- **失败**：无（错误页本身就是失败态）。
- 证据：`interactions.js`「opening a record that does not exist…」；`reviewer-findings-r2.js` R5 / R6（回收站记录横幅 + 恢复）；`reviewer-findings.js` F17。

## I. 跨页面一致性（同一事实只有一个来源）

| 事实 | 写入点 | 必须同步出现的界面 |
|---|---|---|
| 待办标题/截止 | composer、详情内联 | 待办列表、今天、日历泳道、搜索、子任务行 |

| 安排时段 | composer、时间格 sheet、详情、改期 | 待办行、详情执行时间、日历安排块、今天此刻/稍后、未安排归属 |
| 日程 | composer、拖动、改期 | 日历网格、今天、搜索、月视图 chip |
