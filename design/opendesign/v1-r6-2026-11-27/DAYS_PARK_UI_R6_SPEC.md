# DaySpark R6 视觉与交互契约（2026-11-27）

本文件描述 R6 原型实际执行的界面规则。它**不是新方向**：色彩关系、字体气质、顶栏与 Dock、基础组件形态均沿用 PR #113 的冻结视觉；R6 只把尺寸、层级、密度、状态与文案收紧到成熟产品精度。

## 1. 设计令牌

### 1.1 颜色（浅色）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--paper` | `#ffffff` | 纸张、抽屉、浮层底色 |
| `--surface-2` | `#fbfbf8` | 次级卡片、提案卡背景 |
| `--wash` | `#f5f5ef` | 分组底色、悬停、月历星期行 |
| `--ink` | `#181816` | 主文字、主按钮底 |
| `--ink-2` | `#3c3c34` | 次级文字 |
| `--muted` | `#5b5b52` | 元信息、说明 |
| `--faint` | `#73736a` | 分组标签、轴刻度 |
| `--hair` | `#e5e5dc` | 主分隔线 |
| `--hair-2` | `#d4d4ca` | 控件描边 |
| `--hair-soft` | `#efefe9` | 列表行分隔 |
| `--red` | `#bd2a1d` | 逾期、现在、品牌强调 |
| `--amber` | `#83580f` | 截止、计划提示 |
| `--work` | `#4b5f72` | 工作蓝、AI 提案强调 |

R6 只把朱砂、琥珀、工作蓝在原色相上压深一档以提高白底对比度，**没有更换品牌色相**。日历仍用 6 个既有分类色（个人/工作/家务/健康/生活/学习），其色值与 #113 一致。

### 1.2 深色与暖灰

- 深色以 `body[data-proto-theme="dark"]` 切换：纸张 `#252622` 系、主文字反转为浅墨、分隔线降为 `#33342f` 系、工作蓝提亮为 `#9bb7c8`。
- 彩色时间块/日历块在深色中统一用 `color-mix(in srgb, 原背景色 18%, #1e1f1c)` 压成低饱和底，保留左侧 2px 分类色条与标题；计划块用 `#2a2b24` 与蓝色左条区分。
- 暖灰（`warm`）沿用 R4 的纸色偏移，只做对比度对齐，不改结构。
- 墨底控件（品牌标记、发送、主按钮、手机 FAB、勾选）在深色中字形改用纸色，避免“墨上加墨”。

### 1.3 字体与字阶

系统字体栈不变。R6 的常用字阶：

| 角色 | 字号 / 行高 | 字重 |
|---|---|---|
| 页面大标题（日期、页名） | 30 / 1.18 | 650 |
| 手机日期 | 30 / 1.18 | 650 |
| 详情标题 | 24 / 1.28 | 650 |
| 手机详情标题 | 24 | 650 |
| 区块标题 / 设置小标题 | 16 | 650 |
| 列表主标题（桌面） | 14.5 / 1.4，最多 2 行 | 520 |
| 列表主标题（手机） | 16 / 1.4，最多 2 行 | 520 |
| 时间轴块标题 | 14 / 1.35 | 600 |
| 正文 / 详情值 | 13–13.5 / 1.6–1.7 | 400 |
| 元信息 / 标签 | 11–11.5 | 400–560 |
| 分组标签 / 轴刻度 | 10–10.5，字距 .08em | 650 |

原则：**正文不小于 13px，手机正文不小于 12.5px，关键标题不小于 14px**；不再用 9–10px 承载可读信息（轴刻度与分组帽除外）。数字使用 `font-variant-numeric: tabular-nums`（时间、日期、计数）。

### 1.4 间距、圆角、控件高度

- 间距阶梯：4 / 6 / 8 / 10 / 12 / 14 / 16 / 18 / 22 / 24 / 28 / 32。
- 圆角：控件 5–7，卡片/块 8–12，捕获条 29（胶囊），手机 Dock 无圆角贴底。
- 顶栏 58；页头上下 22/15；列表行 62；时间轴行最小 64；设置行 64；详情字段行 46；捕获条 58；手机 Dock 64；手机顶栏 56。
- 桌面内容左右 28–32；手机内容左右 20；≤960 收到 18–22。

## 2. 断点与外壳

| 宽度 | 行为 |
|---|---|
| ≥1240 | 设置页的页头文字、左导航与内容整体居中（最大 1240），内容列 820；导航与标题左缘对齐 |
| 1200–1240 | 正常双栏；详情抽屉 420 内联挤压 |
| ≤1200 | 详情抽屉改为右侧覆盖层（420），底部捕获条与捕获面板在抽屉打开时收起 |
| ≤960 | 顶栏间距收紧、时钟隐藏、页头 26px、列表/时间列内边距缩小 |
| ≤720 或胶囊切「手机」 | 进入 390×844 手机外壳（真机比例），顶栏 + 内容 + 捕获条 + 四入口 Dock |

手机外壳不是缩放版桌面：列表改为 16px 标题、时间块改为「时间 + 卡片」、月历改为圆点、详情改为整页表单。

## 3. 组件语法

### 3.1 顶栏与页头

- 顶栏：品牌 14.5 / 24px 标记，导航 14px、24px 间距，当前项 2px 墨色下划线；右侧搜索（含 ⌘K）、时钟、头像。R6 去掉调试感：原型工具收进右下「预览」胶囊。
- 页头：标题 30 + 副标题 13 同行；下方摘要 12；右侧工具 32 高、圆角 7。
- 工具条与视图切换：同一高度与圆角；选中态用纸底 + 细阴影，不用重色块。

### 3.2 列表行

- 桌面 62 高：18px 圆形勾选、标题 14.5（2 行截断）、元信息 11.5、右侧截止胶囊与行操作。
- 手机 66 高：19px 勾选、16px 标题、12px 元信息。
- 逾期：截止胶囊红底浅色、日期红字；遗漏：`已遗漏 N` 红字；重复：`每周五` 等灰字。
- 行悬停只改底色与操作按钮透明度，不位移。

### 3.3 时间轴

- 桌面行：`58px 时间 + 14px 轨道 + 内容`，最小 64 高；时间 11.5，轨道点为 6px 分类色，外圈与页面底色一致（深色下不再是白圈）。
- 块：圆角 8、内边距 10×12；计划块用 `计划` 小标签与截止提示；进行中用 `进行中` 朱砂标签。
- 现在线：朱砂 1.5px + 左侧端点，左侧留出时间列宽度。

### 3.4 日历

- 月：星期行 36 高；单元格最小 104；日期数字 13；条目 11px，时间前缀用等宽数字灰色；最多 3 条（溢出变体 4 条），其余 `+N`；截止条目用琥珀竖条，计划条目降低不透明度。
- 周/日：08:00–20:00 轴刻度 10.5；块绝对定位并按泳道分栏；高度 < 6% 视为短块（只留单行标题，隐藏元信息与拖拽把手）；多泳道时标题单行、隐藏元信息，避免窄块文字互相覆盖。
- 截止：周视图有独立「截止」行；日/时间轴用虚线标记 + 琥珀标签。
- 手机月历：每日最多 3 个分类圆点（截止为琥珀短横），超出显示 `+N`；下方接当天时间块。

### 3.5 抽屉与详情

- 桌面 420 宽，头部 56，正文 22×24，字段行 46（标签 88 + 值），底部操作固定。
- ≤1200 覆盖层带左侧阴影；打开时底部捕获条收起，避免半截压在抽屉下。
- 手机为整页编辑：标题输入 17、字段标签 11.5、行间 9、底部「保存 / 取消 / 删除」。
- 完成控件是一整行 46 高的可点击区，不用孤立小勾。
- 计划执行行在手机上整行即入口（带右箭头），不再额外追加第二个「再安排一段」链接。

### 3.6 快速捕获

- 桌面条 600×58，胶囊；类型、日期、输入 14.5、回车提示、圆形展开按钮。
- 面板 660 宽：头部（标题+副标题）、解析行、建议行、字段、底部提示与按钮。
- **文案与结果必须一致**：带时刻解析为日程时，标题写「将创建日程」，主按钮「创建日程」，日程信息写明「明天 15:00–16:00 · 个人」；移除时间后改为「将记下待办 / 记下待办」；「移除时间，记为待办」「恢复时间」是真实可逆操作。
- 手机捕获条 58 高，点在输入框上打开同一套面板的底部卡片。

### 3.7 设置

- 左导航按 6 组：账户与同步 / 外观与日历 / 通知与提醒 / 数据与备份 / AI 与自动化 / 关于与诊断；组帽 10px 大写字距，项 13px、36 高。
- 内容按同一组顺序排列，组帽 10.5；行 64：13.5 标题 + 11.5 说明 + 右侧值/动作 12.5。
- 宽屏居中后，标题、导航、内容三者左缘对齐；不再出现右侧 400px 空白。
- 手机设置同分组，组帽 11。

### 3.8 AI

- 每条回复最多一个动作区，且只有**最新一条**带提案卡；旧回复不再重复挂四个通用按钮。
- 提案卡：11px 标题「建议提案 · 待确认」、13px 正文、主按钮「创建这条待办」+ 次按钮「安排时间」。
- 主按钮进入新建待办并预填标题；次按钮打开计划写入确认（选择待办、日期、起止）。两个动作都与文案一致，不再只弹提示。

### 3.9 反馈层

- Toast 11px、深底浅字、底部居中；撤销条位于捕获条之上（桌面 94，手机 138），不遮 Dock。
- 危险操作先确认；确认弹窗 320 宽，主/危险按钮同高。

## 4. 文案原则

1. **动作即结果**：按钮写「创建日程」就创建日程，不写模糊的「保存」。
2. **数字要真**：`另有 1 项今天截止` 的计数来自真实列表；手机「还有 N 项安排」同理。
3. **不替用户决定**：解析可以建议类型，但默认待办；AI 只提案，写入前确认。
4. **少用口号**：说明句优先写清「会发生什么、能不能撤销」。
5. **时间写法**：列表用 `11/20 18:00`、时间轴用 `15:15–16:00`、跨天明确写「次日」；相对日只在明确语境用「明天」。

## 5. 主题与状态覆盖

- 三主题 × 四尺寸的关键页面均已实际渲染截图（见 `evidence-r6/`）。
- 空态、加载、错误、保存失败、冲突、回收站等状态沿用 R4 的结构，R6 只统一字号、间距与按钮高度；未新造状态。
- 悬停/焦点样式保留既有实现；键盘 Enter/Esc、⌘K、N/E/T/W/M/D 等快捷键未被改动。

## 6. 明确不做

- 不换色板/品牌/字体方向，不动顶栏三入口与手机四入口 Dock。
- 不新增业务能力、不改产品范围与商业模式。
- 不重写原型、不重构数据模型、不做竞品调研或多方案探索。
- 不改 Flutter 实现、不合并任何 PR、不宣布最终冻结。
