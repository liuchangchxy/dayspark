01

今天页 · 四个时间节 + 未安排 shelf

原型固定画 11/15 15:00 这一格：现在 1 节、接下来 2 节、今天截止 1、已逾期 2、未安排预览 1 行。四个节与 shelf 的「容量」从未被画过。以下按节逐条问边界。

T1整日为空：四节同时缺失 P1

原型假设

画了 02 空态——但那是次日 11/16 清晨的独立场景（design-notes §16 保留项），主数据集永远是满的。空态文案「今天还没有安排」把「没事件」与「没待办」混成一句话。

真实需要

今天 0 事件但 shelf 有 8 项未安排，或 0 待办但有一条 10 天前逾期房租——这两种「半空」原型都没画。用户对「今天空」的读法取决于剩下那一格是什么。

要拍板的决定

空态必须是按节条件渲染，不是整页二选一：「已逾期」节只在有逾期项时出现，「今天截止」节只在当天有到期项时出现，事件节（现在/接下来）按事件数出。整页全空时文案要能指向剩下的那一格。

四节独立判空，空态文案随剩余格变 整页空 = 「今天还没有安排」（维持原型） 仅逾期在 = 「还有 2 件逾期，处理完就清空」

T2单节 40 项：「接下来」无限长 P0

原型假设

「接下来」画 2 块。design-notes 把 3 行预览 + 「还有 N 项 · 展开全部」只给了「未安排」组，时间轴四节默认永远放得下。

真实需要

真实的一天：「接下来」有 40 个 16:00 起的计划块，「已逾期」30 项。用户打开今天页要滑到屏幕外才看到现在该干什么。「现在」是唯一的锚，它必须永远在视口，而它下面的无限长节把锚稀释了。

要拍板的决定

给时间轴四节一个统一的节内折叠契约（不是只给 shelf）：超过一屏的节（尤其「接下来」「已逾期」）收成「组头 + 前 N 块 + 还有 M 项 · 展开」，N 按剩余视口高度算（沿用 shelf 的 §18.3-7「组头必跟行」规则）。「现在」节永不折叠——它是今天页唯一的当下锚。

「接下来/已逾期」套 shelf 同款折叠契约，「现在」永不折 折叠后「今天截止」若被挤出视口，加顶部 1 行吸顶提示「还有 1 件今天 18:00 截止」

T3同一 Todo 既截止又计划：完成语义冲突 P0

原型假设

画了合并（A″ 规则 4 / design-notes §14）：只画 allocation 块，截止作块内次级 meta「截止 18:00」，不另起一行。但块上只有一个复选框——勾选它到底完成了什么，原型没定义。

真实需要

「整理周会纪要」计划 16:00–17:00、截止 18:00。用户 17:30 勾掉 allocation。此刻截止还在（18:00 没到）。这条 Todo 算完成了吗？「今天截止」节里的它消失了，还是留着等 18:00？用户需要一句可预期的话。

要拍板的决定

合并块的勾选同时完成「该次执行」与「该截止」——一条 Todo 只有一个完成事实，不允许「执行完成但截止仍挂」。勾选后：今天页「已逾期/今天截止」的计数 -1，块视觉降为 done-ink，meta 追加「已于 17:30 完成 · 原截止 18:00」。若用户想保留截止（比如只想先做、截止另算），那必须走 composer 显式拆字段，而不是靠勾选的副作用。

一勾双完，meta 记录「提前完成」时刻 反方案：勾选只完执行，截止留到 18:00 自动核销——被否：制造「完成了还挂着」的鬼状态

T4重复项完成：同一次发生可撤销 P0

原型假设

原型全是单次待办，没有任何重复项（recurring）。勾选完成 = 该行变 done。重复实例的完成、撤销、对「下一次」的影响，原型一笔未画。

真实需要

「每周一 给房东转房租」周一完成了。用户 10 秒后反悔——这个反悔必须落在同一周一这次发生上，不能把整个重复序列取消，也不能误改「下次周一」。撤销粒度 = 本次发生（occurrence），不是序列（series）。这是整个评审板最高优先级的数据模型决定。

要拍板的决定

重复项在数据层要把「实例」物化：每次发生是一个独立 completion 记录，撤销只回滚本实例，序列规则（每周/每日/自定义）不动。UI 层：勾选后 5s 撤销窗（inline undo，仿捕获行 toast 语言「已勾选 · 撤销」）；撤销窗关闭后，本实例永久完成，「下次」照常生成。完成态行必须能读出「这是重复项的第 N 次」，否则用户无法判断自己撤销的是哪一次。

occurrence 物化 + 5s 同实例 undo 撤销窗内重复项行保留 occurrence 序号（「第 12 周」） 被否：序列级撤销（太危险）、完成即删块（丢 occurrence 历史）

T5DayProjection 加载失败：今天页降级 P1

原型假设

今天页永远显示完整投影（§16.2 的 Events + Allocations + 当天到期 Todos）。没有骨架、没有失败、没有重试。原型假设数据永远在场。

真实需要

冷启动 / 离线 / 同步失败时，今天页是用户一天看的第一屏。空白或白屏 = 「我的日程呢？」。失败时用户需要知道：是还没拿到数据，还是真的空，以及怎么重试。

要拍板的决定

今天页三态：①首载 = 骨架屏（四节占位，沿用行几何 52px，不画假数据）；②失败 = 空态盒 + 一句「同步失败，显示的是本地最后已知」+「重试」链接按钮（primary 文字，非实心）；③成功但空 = 现有 02 空态。失败态要标出数据新鲜度（「本地 · 上次同步 14:20」），否则用户会误以为是全量。

失败态 = 本地最后已知 + 新鲜度戳 + 重试 离线时隐藏「已逾期」节（依赖同步的判定），只保留本地待办
02

日历 · 24h 轴 / 截止 lane / 槽 sheet 三动作

原型只画了月视图（手机），实现版跑的是完整 24h 可滚日/周轴 + 截止 lane + 点槽弹 sheet。原型 14 号屏的三动作（新建日程 / 安排待办 / 新建并安排）现在要接受信息层级拷问。

C1槽 sheet 头部：真实时间范围该不该上头 P0

原型假设

14 号屏 sheet 头 = 「11月15日 · 周日 · 18:00–19:00」，时间范围写死在头里。原型没问：当用户点的是一个空槽（比如 22:00）而非一个事件时，范围从哪来？

真实需要

24h 轴上点空白弹 sheet 时，「范围」是用户点的槽 + 默认时长（默认 1h？30min？）。用户需要一眼看出「我这一戳对应的是几点到几点」，否则三个动作写进去的时间是猜的。头部必须带真实起止，且标出「默认时长」是推断值——这是可编辑的，不是事实。

要拍板的决定

sheet 头改双行：主行 「11月15日 · 周日」（日期是事实），次行 「18:00–19:00 · 默认时长，可改」（范围是推断 + 可编辑控件入口）。点事件进 sheet 时次行改为「18:00–19:00 · 既有日程」（事实，不可改）。三个动作都引用同一个已解析范围，不允许各写各的。

日期作主行，范围作次行 + 「默认/可改」标签 默认时长 = 1h（30min 粒度），随 slot 上沿对齐 30min

C2三动作视觉权重：是否要分级 P1

原型假设

三个 srow 等重（同 15px/600 标题 + 15px/400 说明），只有「安排待办」右侧带 chevron。视觉上一个都不比另一个重。

真实需要

三动作语义严格不同（写 Event / 写 allocation / 写 allocation+todo），但频率严重不均：「新建日程」是主路径，「安排待办」要二级 sheet 选项，「新建并安排」是组合捷径。等重 = 用户每次都要读三遍说明。主路径要一眼可辨。

要拍板的决定

按频率 × 不可逆性分级，不是按语义重要性：①「新建日程」= 实心 primary 行（sheet 内唯一实心，与 composer 主按钮同语言）；②「新建并安排」= surface-2 描边行；③「安排待办」= 纯文字行 + 右侧 chevron（进二级 sheet，最重操作放最后）。权重递减 = 可逆性递增。

实心 → 描边 → 文字，按可逆性排 「安排待办」前加「未安排」项数徽标（0 时整行 disabled + 说明「未安排里没有待办」）

C3候选待办列表：空 / 错状态文案 P1

原型假设

「安排待办」二级 sheet 只画了「有候选」：列当天未安排项，带截止的排最前。没有空候选、没有加载失败、没有「全被安排了」的中间态。

真实需要

点槽想安排待办，但未安排里一条都没有（全排掉了），或同步失败读不到未安排列表。空 ≠ 错，文案必须分开，且空态要给出下一步（去新建）。

要拍板的决定

二级 sheet 三态，文案固定如下（复用 .empty 空态盒语言）：

空（未安排里没有待办）
「未安排里没有待办可安排」 + 「先去记一条，或直接用上面「新建并安排」」
↑ 指向 sheet 内的「新建并安排」行
错（读未安排列表失败）
「未安排列表没加载出来」 + 「可新建日程，或重试后再安排待办」
重试 · 新建日程仍可用

关键决定：「安排待办」失败不连带禁掉「新建日程」——两个动作的数据源独立，错误只隔离到「安排待办」一行。

错误只隔离到失败动作，不整 sheet 报错

C424h 轴：原型 12:00–18:00 窗口 vs 全轴 P2

原型假设

周/日视图画 12:00–18:00 六行窗口（§16 修 F），超出滚动。实现是完整 0:00–24:00 可滚轴。两版的「现在线」位置、截止 lane 是否跟随滚动、凌晨时段空块，从未对账。

真实需要

24h 轴上，现在线 + 截止 lane 必须 sticky 跟随滚动，否则滚到凌晨 2:00 时用户失去「现在在哪」与「今天几点截止」两个锚。凌晨空时段要能快速跳回现在，而不是从 0:00 滑一小时。

要拍板的决定

① 现在线 = 吸顶线（滚到视口顶时钉在顶，带时刻读数）；② 截止 lane 作独立的 sticky 顶条，不随时间格滚走；③ 加「回到现在」浮动键（仅当滚离现在 > 1 屏时出现）。凌晨 0–6 点空轴用低对比度折叠段（一行「凌晨 · 无事」），不画 7 个空小时。

现在线 + 截止 lane 双 sticky，凌晨折叠段 「回到现在」键 = 24px 圆形，贴右下角，不与 FAB 同屏

D2「安排」作为独立动作：语义与去向 P0

原型假设

「安排」在原型里 = 点行进 composer（design-notes §3「点行 = 进 composer 安排」）。它没有和「打开/查看详情」分开——整行既是查看又是安排的入口，语义混在一个手势上。

真实需要

一条未安排项，用户只想给它排个时间，不想进全字段 composer 改标题/截止/备注。把「安排」和「打开」绑死，意味着每个纯排期动作都要穿过一个 6 字段的表单。安排必须是可直达的轻动作。

要拍板的决定

「安排」直达 composer 的 schedule 模式：标题只读锁定（这是既有待办，不是新建），只露「计划执行时段」+「（可选）截止」两行 + 主按钮。与 D1 的行右缘「安排」键配对。整行点 = 进全字段详情（查看/编辑），右缘键 = 进 schedule 模式（只排期）。一个字段两种进入深度，由入口决定，不由用户猜。

schedule 模式 = composer 锁标题的轻子集 schedule 模式主按钮文案 = 「安排到 11/17 14:00–15:00」（见 A4 状态矩阵）

D3可撤销的完成态：已完成行长什么样 P0

原型假设

done 行 = 标题 strike-through + ink-3 灰 meta「已完成」（M15 第 3 行）。这是终态画法——做完就是做完，原型没给「刚做完、还能反悔」的中间态。

真实需要

配合 T4（重复项同实例撤销）+ D2（轻完成），勾选后几秒内用户可能反悔。终态画法把反悔的唯一路径藏进「再点一次复选框」，用户不知道还能撤销，也不知道撤销的是哪一次发生。

要拍板的决定

完成行加一个 5s 可撤销窗，窗内行 = 终态视觉 + 行右缘一个 「撤销」键（primary，仿捕获行 toast 的 undo 语言）。窗关闭后「撤销」键消失，行回落纯 done。重复项完成时「撤销」键读作「撤销第 N 次」，把 occurrence 暴露出来。撤销窗内该行保持原位不移走（不滑到 done 区），避免布局跳动。

04

Composer · 一 sheet 两模式（创建 / 安排既有）

原型 09/10/11 是创建模式（标题可填、按钮「保存到未安排 / 计划执行到 / 保存（截止）」）。实现版同一个 sheet 还要承担安排既有待办（D2 的 schedule 模式）。主按钮必须永远说出「会写下什么」。

P1主按钮命名：创建 vs 安排既有，两套文案 P0

原型假设

主按钮只覆盖创建模式三态：「保存到未安排」/「计划执行到 11/17」/「保存（截止 11/17 18:00）」（design-notes §8 第 5 条）。按钮文案 = 结果的承诺。但安排既有待办时，待办已经存在，「保存」这个动词是错的——没有新东西可保存。

真实需要

schedule 模式的主按钮必须读作「写到哪」而非「存一个新条」。用户要确认的是「这条既有待办会被排到 11/17 14:00–15:00」，不是「创建一条」。动词错了 = 用户以为会新建一条重复的。

要拍板的决定

主按钮动词随模式切换：创建模式用「保存…」；schedule 模式用「安排…」（「安排到 11/17 14:00–15:00」）。两者共享同一套「带出实际值」的命名规则，只换首动词。schedule 模式下标题区只读展示既有标题（非输入框），按钮区上方加一句「将更新「整理周会纪要」」，把「改的是这条」说死。

动词随模式：保存 / 安排，值永远内嵌

P2状态矩阵：nothing / due / slot / both / schedule P1

原型假设

画了创建模式的 3 个状态（未选 / 选时段 / 设截止）。「截止+时段同时有」与「schedule 模式」未画，按钮文案也没有覆盖到「both」。

真实需要

组合态里按钮最容易被写错：既设了截止又选了时段，按钮该说什么？schedule 模式里「只选时段不动截止」又该说什么？每个组合都要唯一可预测的文案，不能让用户去猜按钮会写什么。

要拍板的决定

按钮文案 = 「动词 + 将写入的每个字段（带值）」，多字段用「·」连接，谁设了谁出现。固定矩阵：

状态（创建模式）主按钮文案校验
nothing（啥都没选）保存到未安排✓ 原型已有，纯捕获
due only保存（截止 11/17 18:00）✓ 原型已有
slot only计划执行到 11/17 14:00–15:00✓ 原型已有
both保存（计划 14:00–15:00 · 截止 18:00）未画——必须补，且「计划」在前（主行语义）
schedule · slot only安排到 11/17 14:00–15:00未画——动词换「安排」
schedule · due+slot安排（计划 14:00–15:00 · 截止 18:00）未画——既有待办改截止也要说死

规则：只列已变化的字段（schedule 模式里没动的截止不重复进按钮）；多字段按「计划 → 截止」固定序；值一律 tabular 内嵌。

P3两模式切换：同 sheet 内 create ⇄ schedule P2

原型假设

composer 是一开一关的 sheet，创建模式从「安排到这一天」/ 时间槽打开。没有「在已打开的 composer 里切换成 schedule 模式」的路径。

真实需要

用户从「未安排」进 schedule 模式排了期，中途想把这条拆成新的待办或改回创建。两模式在同一个 sheet 里要可切换，且切换时已填字段不丢。

要拍板的决定

sheet 头加一个模式切换段控（创建 / 安排既有，仿 .sh-head 的 seg 语言）：切到「安排既有」时标题输入框变只读、主按钮动词变「安排」；切回「创建」时标题解锁、按钮变「保存」。切换不清空已选时段与截止。schedule 模式下若该待办已被排期，进入即预选其既有时段（不是空白），避免误改。

seg 切模式，字段保留，schedule 入口预填既有时段

X1七个风险点逐一定性

R1
丢工作③ 写 allocation 静默失败：composer 保存报网络错时，若只 toast「保存失败」不保留草稿，用户已填的标题+时段全丢。决定：失败不清空 composer，草稿留 sheet 内，按钮旁标「未写入」。
R2
丢跟踪③ 安排完不回跳：在「按日期」排了 11/17，但用户停在 11/15 屏。决定：成功后 sheet 关，browseDate 自动跳到被安排的日期并弹「已安排到 11/17 · 查看」一行。
R3
丢跟踪④ 上日历要手动翻：安排到的日期不在当前视图。决定：日历页收到「有新安排」后，月视图在目标日格上短暂 primary-tint 闪烁（1.2s，非持久），周/日视图自动定位。
R4
丢工作⑤ reschedule 旧 allocation 未清：改排到 11/18 若旧 11/17 的 allocation 没删，同一条待办双挂两日，勾选其一另一日仍显示未完成。决定：改排 = 原子替换（删旧 + 写新同一事务），不允许产生两条 allocation。
R5
丢跟踪⑥ 完成不联动：在日历块勾选后，「今天/未安排」的计数与 shelf 没更新。决定：完成是单一事实源事件，所有页（今天四节计数、未安排 shelf、按日期列表）订阅同一事件即时刷新，不靠用户切页重算。
R6
丢工作⑦ 撤销窗过后不可逆：5s 窗是唯一的反悔机会。决定：窗过后，完成记录进「最近完成」可检索（今天页加一隐藏节 / 待办·全部加「已完成」段），从那里可重新打开——完成不被物理删除，只移区。
R7
丢跟踪⑦ 重复项撤哪一次：撤销粒度是 occurrence，但 UI 没暴露「第几次」。决定：重复项完成行必带 occurrence 序号（「第 12 周」），撤销键读作「撤销第 12 周」，与 T4 / D3 一致。
