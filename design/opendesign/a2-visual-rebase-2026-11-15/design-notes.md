# DaySpark「灵光」A″ 交互模型 · UI 原型设计说明

本文件逐条回答任务书第五节「必须由你拍板并画出来的决定」，并给出关键尺寸。
视觉基线 = 已验收的 Direction C（安静纸墨）；产品语义 = 已确认的 A″，未做任何改动。
所有尺寸单位为逻辑 px（Flutter 侧按 1.0 逻辑像素 1:1 映射）。

---

## 1. 页面层级与每屏唯一主创建入口

| 屏 | 唯一主创建入口 | 位置 | 形态 |
|---|---|---|---|
| 今天 | 捕获行 | 列表底、dock 上 | 吸底输入行（非 FAB） |
| 待办·未安排 / 全部 | 捕获行 | 同上 | 同上 |
| 待办·按日期 | 「安排到这一天」 | 吸底条（dock 上） | 44px 实心主按钮 + 说明行 |
| 日历 · 月 | FAB | 右下浮动 | 52px 圆形 FAB |
| 日历 · 周 / 日 | 时间槽 sheet | 点空白槽弹层 | 无 FAB——周/日的主创建入口就是「点时间槽」，再放 FAB 会变成两个入口，且会压住 17:30 的块 |

**语义边界**：捕获行只创建「待办（Todo）」——它不写 Event，也不写 TaskAllocation；新建日程只能从日历的时间槽（14）进入，因为 Event 必须有明确起止时间。Today 的「今天截止」节只读展示当天到期的待办，勾选才写完成态。

**规则：捕获行与 FAB 永不同屏。** 日历页不渲染捕获行；今天/未安排/全部页不渲染 FAB。桌面没有捕获行与 FAB，创建入口收进顶栏「+ 记一笔」icon（今天/待办）与日历双击空白（等价于时间槽 sheet 的三个动作）。

## 2. 捕获行（今天 / 未安排 / 全部）

- **尺寸**：整行高 52px = 8 上 pad + 36 内容 + 8 下 pad；左右边距 16。
- **构成**：32px 实心圆「+」icon（primary 底 on-primary 图）+ placeholder 文本 15px ink-3 + 右侧提示「⏎ 进未安排」11px ink-3 tabular。
- **placeholder**：今天页「记一笔 · 回车直接进『未安排』」；未安排/全部同文案（它们本来就是进未安排）。
- **键盘态**：键盘打开时 **dock 被键盘顶替**（不叠加），捕获行吸在键盘顶边，列表自动上移避让，**并滚到「未安排」组**（新加的行必须在视口内，不能要求用户再滑）；键盘高按 iOS 默认 288px 布局（32 键高 × 4 行 + 功能行 + home 区 34 保留给系统）。键盘「加入」键 = 提交（主色文字，非实心按钮——一屏仍只有一个实心入口是捕获行的「+」圆钮，键盘提交键属系统键盘不在此规则约束内）。
- **连续提交反馈**：提交后焦点不离开输入框；轻 toast（ink 底、圆角 999、高 30，显示 1.5s）「已加入『未安排』· 继续输入」悬浮在捕获行上方 8px；同时未安排组顶部即时插入新行，新行带 1 行高 primary-soft 底色 + meta「刚加入」标记（3s 后底色消退）。不打断输入、不弹键盘收起、不跳页。
- **触控**：整行可点聚焦（44px 命中区 = 整行高 52）。

> **Visual Rebase 后的捕获行**：48 高、无边框、顶部 1px `line-soft`，左侧「+」是 **16px `ink-3`**（Direction C 的 `TodoQuickAdd` 画法），不再是 32px primary 实心圆。一屏唯一的实心主按钮交给 composer 的底部按钮与日历 FAB。

## 3. Today 的「未安排」组如何呈现

- **位置**：时间轴「已逾期」节之后，组头 12px 600 + 计数（ink-3），与全量「待办·未安排」视图同构但截断。
- **超过一屏时**：今天页整列可滚动（现在/接下来/今天截止/已逾期 → 未安排组），捕获行与 dock 固定不动；捕获行上沿只有 1px `line-soft` 发丝（**不用渐隐遮罩**——Direction C 没有任何渐变）。未安排组放在最不紧急的位置是刻意的——它不参与时间轴。
- **默认行数**：3 行 + 末行「还有 N 项 · 展开全部」（13px 400 ink-3，无复选框行，可点）。3 是 SPEC 规则 20 定死的上限；展开后全部列出，组头箭头翻转 180°。
- **一屏放得下几行就画几行**：01（正常内容）与 DARK 按 Direction C 的块高排完时间轴后只剩 64px，所以画 **1 行预览**（组头 8 项 + 1 行 + ⌃）；03（键盘态）整屏只有这一组，画 **3 行 + 「还有 7 项 · 展开全部」**。组头永远跟着行，不留只有组头的悬空段；「最多 3 条」是上限，不是下限。
- **与全量视图关系**：Today 的未安排组 = 全量未安排中**只取无 dueDate 的项**前 3 条（按日历归属 + 创建顺序）；全量在「待办·未安排」看。两处数据同源，Today 只负责"提醒还有事"，不承载全量管理。
- **带截止的未安排项是否出现在 Today**：**不出现**。判据 = 有 dueDate 且无 TaskAllocation。带截止的未安排项只进「待办·未安排」的「带截止·未安排」段（暖褐 meta「建议 N 前」）与「全部」。理由：Today 已逾期节已经承载"该急了"的信号，再混入未截止的未安排带截止项会把「逾期」与「建议尽快」两种不同语义搅在一起；用户想处理它的路径很明确——去未安排。
- **组内行高**：52px（与 TodoListTile 完全一致），**带复选框**（48 触控 / 20 视觉圆环 / 1.5px ink-3），勾选 = 完成，点行 = 进 composer 安排。展开入口行例外：无复选框、无日历点。

## 4. 时间轴里 Event / TaskAllocation / 纯 deadline 的视觉区分

> 本节 = Visual Rebase 后的版本（2026-11-15）。旧的「primary-soft 填充 + 虚线边框 + 18px 小圆环」已全部废弃。

| 元素 | 填充 | 左条 | 边框 | 可勾选 | 文字 |
|---|---|---|---|---|---|
| Event（日程） | 归属日历色 10%（浅色）/ 16%（深色），叠在 surface 上 | 3px 归属色（cal-1…4） | 1px `line`，6 圆角 | ❌（点块进事件详情） | 标题 12/600；meta 12/400 `ink-3` |
| TaskAllocation（计划执行） | `work-tint` | 3px `work` | 1px `line`，6 圆角 | ✅ 48 触控 / 20 圆环 | 同上；「计划执行 16:00–17:00」12 `work` |
| 纯 deadline 的 Todo | `surface` 白底 | 3px `warn`（逾期 `danger`） | 1px `line`，6 圆角 | ✅ 同上 | 同上；「截止 18:00」用 `warn` / 逾期用 `danger`，右侧「去安排」chip |

**关键约定**：
- **全项目不画虚线边框**（Direction C 没有虚线；区分只靠归属色 + 左条 + 可勾选）。
- 同一 Todo 既截止又计划（A″ 规则 4）：只画 allocation 块，截止时间作为块内次级 meta「截止 18:00」；**不另起一行**。
- 块高度由内容决定，最小 40px；块间距上 2 / 下 4。标题最多两行（App 的时间块是单行省略，但 A″ 的块承载整条待办标题，截断会丢信息 —— 这条差是自觉的）。
- 时间列 64px（Direction C 的日轴是 52：52 轴 + 46 右槽；A″ 的堆叠列表用 64 让时间 + 时长两行都放得下）。
- 小节头（现在 / 接下来 / 今天截止 / 已逾期）30 高、18 左距、5px 圆点 + 11/600 字、右侧计数 11 `faint`；「现在」走 `primary`、逾期走 `danger`。

## 5. 复选框尺寸 / 位置 / 触控区

- **所有行内与块内统一**：视觉圆环 20px、1.5px `ink-3` 边框、触控区 48×48、行左 12 起、圆环与文字间距 12。
- **完成态**：`primary` 实心 + 白勾 12.4；标题 strike-through + `ink-3`。**不再使用绿色**（Direction C 的勾选就是 primary）。
- 块内完成不删块（时间轴保留占位，视觉降为 `done-ink`）。
- App 里有 `DsCheck(compact: true)`（触控区 36、圆环仍是 20），只用于非列表场景；原型里不使用小号变体，避免出现「两种勾选」。

## 6. 日期条、日期头、月年选择器的关系与状态

- **今天页**：顶部日期头（纸面底、高 54 = Direction C 的 TopBar 高度）= 只读时钟式：「今天（20/600）+ 2026年11月15日 · 周日（11 ink-3）+ • 现在时刻（12/600 primary）」，无 chevron、不可点。无日期条、无选择器入口——今天永远等于真实今天（A″ 规则 1、6）。
- **待办·按日期 / 日历**：顶部是**日期条**（高 56）：主行「今天」或「11月17日 周二」（17px 600）+ 次行「11月15日 周日 · 2026」或「2 天后 · 2026」（12px ink-3 tabular）+ 右侧 primary-soft 圆角钮（28×28 内 16px chevron-down）。**点日期条 = 打开月年选择器**；点「今天」= 跳回今天。
- **月年选择器**：半屏 sheet，**高 = 屏高 78%（约 650），宽 = 屏宽 390**；头部三段：「月/年」段控（左）+ 标题「2026 年 11 月」（中，17px 600）+ ‹ › 翻页（右）。月模式 = 7×6 日网格（格 44 高，4px 间隙，左右 20 pad）；年模式 = 3×4 年格（格 56 高）；跨年切换时标题与年格均显示完整年份「2025 / 2026 / 2027」。点选日/年即写 browseDate、关闭 sheet、日期条更新。
- **日历 tab 的月视图**与选择器同构但**全屏**（占满列表区、无 sheet 遮罩），‹ › 可连续翻页，底部无选择器 foot；两视图共享同一 browseDate。
- 切 tab（待办↔日历）不改 browseDate（共享）；切到「今天」tab 后 browseDate 保持不动，下次切回时还原。

## 7. FAB 与底部 Dock / 安全区

- FAB **48×48 / 8 圆角 / primary 实心**（Direction C 的 FilledButton 语言，不再是 Material 圆形 FAB），**只在日历月视图**渲染（周/日视图没有 FAB，创建走时间槽——与 §1 同一口径）；**right 16px，bottom 72px**，阴影只有一级 `0 1px 2px rgba(20,20,16,.05), 0 2px 8px rgba(20,20,16,.10)`。
- 月视图 6 行等高铺满，FAB 悬在末行右下角上空（压住末行最后两格的空白，不遮任何数字与圆点）；周/日视图内容区在 FAB 上方留 120px 下 pad。
- FAB 点击弹动作菜单（14 的 sheet 同源）；dock 上「日历」tab 选中时顶线 3px primary 标记。

## 8. Composer 字段层级

自上而下（半屏 sheet，宽 390，高 ≤92%）：

1. 标题行「安排到 11月17日 · 周二」15px 600 ink-2（左）+ 关闭钮（右，surface-2 圆底 32）
2. **标题输入**：20px 600，下边线 1px line，placeholder「要做什么？」
3. **截止行**与**计划执行行**——两条并排的独立字段行（各 min-h 48，8 圆角，1px 边，左右 16 pad，行间 8）：
   - 截止行：左 icon（warm 色 16px 时钟）+ 标签「截止」13px 500 + 右值 13px tabular；有值时 fv 变 warm 600，行底变 warm-soft、边变 warm；无值显示「未设置」ink-3。
   - 计划执行行：同构，但语义色 = primary；有值时行底保持白、边 primary、值 primary 600。
   - **两行之间不共用底、不套卡**——并排时一眼可分的关键：截止是暖褐族（强调"最后期限"），计划执行是钴蓝族（强调"你打算何时做"）；各自下方跟一条 11px hintline（截止=「最晚完成时间，过了算逾期」warm；计划=「你选定的执行时段；完成它不等于到截止」primary；未选时段时计划行 hint=「不选时段直接保存，这条会进『未安排』」）。
   - 计划执行值下方 = 时段 chips：**3 列 × 2 行**（5 个推荐时段 + 「自定…」），单格 8 圆角 12px 500 居中，选中 = primary-soft 底 + primary 边 600；「自定」开滚轮选 start/end（30 分粒度）。3 列是 390 宽下 5 枚同行会挤压到 <64px 的实测结果。
4. 次级字段（折叠单行，13px，行间 2px hairline）：提醒 / 所属日历 / 优先级 / 备注，右侧 chevron。
5. **主按钮**（44 高，8 圆角，一屏唯一实心）：文案随状态——未选时段「保存到未安排」；选了时段「计划执行到 11/17」；设了截止「保存（截止 11/17 18:00）」。右侧 ghost 钮（44，线框）= 更多（删除/复制）。

**创建契约的可见化**（A″ 规则 3）：composer 从「安排到这一天」打开时**不预填任何时段**，计划执行行默认「不选 = 纯捕获」+ 主按钮「保存到未安排」——用户不看 hint 也能从按钮文案读出"不选时段 = 纯捕获"。唯一会预填 start/end 的入口是日历时间槽「新建并安排」（14）。

## 9. 空状态

- **今天空**：列表区全空，居中 56px 灰圆 icon（outline 24 网格）+「今天还没有安排」17px 600 +「想好的事随时记下来，回车直接进『未安排』」13px ink-3；**捕获行仍在**（空状态不删捕获入口）。不显示「现在/接下来/已逾期」节头。
- **未安排空**：「未安排里什么都没有」+「捕获一条，回车就进这里」。
- **按日期空**（browseDate ≠ 今天）：「这一天还没有安排」+ 右侧「安排到这一天」吸底条仍在（这是该日的主入口，空不是删它的理由）；今天 browseDate 空 = 同今天空。

## 10. 滚动、吸底、底部安全区

- 列表区 `overflow: hidden`（Flutter: SingleChildScrollView + 固定高度区）；吸底元素（捕获行 / 吸底条）是 flex 布局的**固定 footer**，不悬浮在列表上，列表在 footer 之上滚动——最后一行永不被遮。
- 底部安全区：home 条 34px 保留在 dock 之下（dock 56 + home 34 = 90 底区）；FAB 按第 7 条计算。dock 的计数（待办 11）是 tab 图标右上角的小徽标（9px，不另起一行）。键盘态：键盘顶替 dock + 保留 home 条位（iOS 键盘自带 home 区，Flutter 里键盘出现时 home 条隐藏、键盘自身占位）。
- 长标题：最多 **2 行**，`overflow-wrap: break-word`（Flutter: maxLines: 2 + overflow: TextOverflow.ellipsis + 软换词），行高随内容从 52 长到 76，不裁切。
- 横向：所有屏 390 宽内无横向滚动；时间列 52 + 内容列自适应，meta 单行 ellipsis。

## 12. 深色（今天页）

仅今天页必须交付深色。token 映射（色相不变、对比达标 ≥4.5:1）：bg #131312 / surface #1c1c1a / surface-2 #262623 / ink #eceae4 / ink-2 #b3b3ab / line #2e2e2b / primary **#7ba3d4**（提亮）/ warm **#cf8f72** / danger **#d08a80** / success **#7fb08f** / nav-bg #171716；日历归属色同步提亮（cal-1 #7fa3c0 / cal-2 #92ad7f / cal-3 #bfa878 / cal-4 #a48aa9）。深色下事件块 primary-soft 变 #1d2733；nowline 与逾期色用提亮 danger。深浅切换走系统，原型在 screens-today.html 末尾给深色对照屏。

## 14. 自检结论

- 390 宽：所有屏内容列 = 370（框内），时间列 52 + 左 pad 12 + 右 pad 16，meta 单行 ellipsis——无横向滚动、无文字溢出。
- 键盘态（03）：dock 被键盘顶替，捕获行贴键盘顶，未安排组最后一行在可视区内（键盘 288 + 捕获 52 + 内容 ≥180 可滚）。
- 遮挡：FAB 仅日历页，月/周内容区底部预留 126px，最后一行不被遮。
- 深浅色：今天页深浅双版均在 screens-today.html。
