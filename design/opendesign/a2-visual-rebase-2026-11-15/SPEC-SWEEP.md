## Verdict

The re-skin is recognisably Direction C over most of the surface — the token table, the 54px phone bar, the 56px dock geometry, the todo row (52 / 48 / 20 / 1.5 / 15-400 / 12-400), the group head (30 / 18 / 5 / 11-600 / 11-400 faint), the mobile block anatomy (6 / 1px / 3px / 12-600 / 12-400), the desktop top bar (56 / brand 22 / wordmark 15-600 / nav 28-r6 / quick add 28 / search 36) and the picker's DsSegmented all match the app — but it is not yet a clean Direction C app: eleven P1 departures remain, concentrated in the A″-only modules (the composer's 44px boxed field rows with swapped deadline/execution glyphs, the slot sheet with tinted icon tiles and no 20px title, the 18px capture gradient, the 9px dock badge) and in the calendar week view (work-tinted allocation blocks instead of the app's dashed outline, a now line that is off-grid and invisible in the week screen, day headers that do not share the grid's column math), plus a desktop task list that runs on a third, smaller row geometry. These read as "this screen belongs to a different app", not as polish, so the skin should not be accepted until the P1 table is cleared; the P2/P3 items are tightening.

## No Direction C analogue (human ruling needed)

These elements have no counterpart in the shipped app, so "correctness" cannot be measured against Direction C. They were excluded from the findings above except where a reused Direction C primitive could be judged.

1. **Device shell** — `.phone` frame, dynamic island, `.statusbar`, home indicator (`shared.css:206-241`) and the fake iOS keyboard `.kbd` (`:460-473`). OS chrome, not app UI.
2. **Deck chrome** — `.proto`, `.flow-strip`, `.flow-band`, `.board`, `.board-cap`, `.board-note` (`shared.css:148-205`) and all of `index.html` (local `<style>` `:7-74`, legend `:23-33`, cards `:40-51`). Presentation layer; it also re-declares tokens locally (drift risk) and uses 14px text / radius 12.
3. **Month/year picker date grid** — `.cal-grid` (`shared.css:546-574`; `screens-todo.html:368-414`). Direction C has no custom date picker; only three theme values are set and M3 defaults are unspecified (`03 §6`: "A CSS reproduction must either copy the M3 defaults or treat this surface as out of scope"). Note the deck's own note (`screens-todo.html:427`) promises a 2px today ring and a solid-circle selection that the CSS does not render (it renders a `primaryTint` cell and a 44px r8 filled rounded square).
4. **FAB** (`shared.css:764-771`; `screens-calendar.html:111`). The app has no FAB anywhere (`01 §5`); 48 / r8 / primary is a plausible build from DsButton, but existence and placement cannot be judged. Its shadow is judged separately (P2 #27).
5. **Today's bottom-docked capture row** (`shared.css:450-458`; `screens-today.html:124-128`). Direction C has no inline capture on Today (top-bar plus → chooser sheet); the row is derived from `TodoQuickAdd` (48 high, 16px plus ink3, gap 8, 15/400 ink3, no border but a bottom hairline), so only that mapping is judgeable.
6. **A″ timeline section heads** 现在 / 接下来 / 今天截止 / 已逾期 (`shared.css:434-443`). No such heads exist in Direction C (`02 §8.1`); DsGroupHead is the nearest component. The 30 / 18 / 5px dot / 11-600 core maps; the rule line and trailing value do not (P2 #13).
7. **Time-gutter duration sublabels** ("45 分", "30 分") (`shared.css:387`; `screens-today.html:49,71`). The app's axis shows HH:00 only; durations live in block meta.
8. **"去安排" action chip inside blocks** (`screens-today.html:87,100,112`). No such widget exists (`02 §8.2`); it borrows the due-capsule geometry (r4, 11/500).
9. **Single-row date strip + month/year sheet on the Tasks tab** (`shared.css:275-288,516-544`; `screens-todo.html:218-221,354-417`). Direction C's Tasks tab uses a 68px 10-cell DayStrip plus a 30px view switch; this module is new and reads as top-bar language.
10. **"安排到这一天" plan bar** (`shared.css:494-509`; `screens-todo.html:247-250`). No analogue; the full-width 44 / r8 primary button is closest to the month rail's "New Event" button (`calendar_month_view.dart:552-594`).
11. **`.fab-menu`** (`shared.css:773-784`). Defined but unused in markup; no analogue.
12. **Desktop 320px todo detail pane** `.ddetail` (`shared.css:903-924`; `desktop.html:199-220`). Direction C panes are 400 (Calendar) or Expanded (Todos) with 58px label/value rows; a fixed 320 key-value pane is a new module. Its field rows are still judged (P2 #23).
13. **Desktop 320px "未安排" side pane** `.dcol.dside` (`shared.css:877`; `desktop.html:120-137`). A″-only; Direction C's Today panel is a 356px task list with 48px rows, not an inbox preview.
14. **Desktop creation model** (top-bar 记一笔 + calendar double-click, `desktop.html:13,310`). Interaction, not visual; no screen to judge.
15. **Dark-mode coverage** — only Today has a dark screen (`screens-today.html:417`), so dark tokens for the other three screens cannot be reviewed for contrast; Direction C defines dark values for every token.
