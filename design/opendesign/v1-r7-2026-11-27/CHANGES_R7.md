# R7 实际修改说明

> 本文件保留 R7 首轮的逐项说明；**第二轮（剩余缺陷修复与完整验收）**的改动集中记在文末「11. 第二轮修复」与「12. 功能覆盖核查落地的改动」，并把首轮遗留的"真实剩余问题"更新到当前状态。

基线：PR #119 / R6 最终提交 `95b63eb`。R6 目录 `design/opendesign/v1-r6-2026-11-27` 原样保留，可独立打开。本轮是增量收敛，不是重做。

## 1. 一个新建入口（修正入口不稳定）

- 桌面顶栏右侧新增「＋ 新建」；手机今天顶栏补「＋」。今天页头不再重复放第二个「新建」，一屏只有一个主入口。
- 点开只有一个选择：**待办**（默认无截止、无计划，先落未安排）或**日程**（预填下一段可用时间）。选完直接进对应整页表单，输入框立即可用。
- 待办页仍默认创建待办，日历页仍默认创建日程；两边都能主动切换类型（`new-type-todo` / `new-type-event`）。
- 直接输入 + 回车 + 连续录入保留；捕获条回车后仍是「已加入未安排 · 继续输入」并回焦。
- 捕获面板仍可展开为完整字段表单；继承日期与时间槽上下文，不擅自给待办写截止。

## 2. 统一的日期导航（修正导航不便、切视图丢焦点）

- `dateStrip` 补三段真实控件：**今天**、**上一天 / 下一天**，与原有 7 天带、月份跳转并存。
- 待办 · 按日期与日历日视图共用同一条规则；日历顶栏的「今天」也改成同一实现，落在同一个 `selectedDate`。
- 切视图保留日期焦点：月 → 周 → 日 → 待办按日期读的都是同一个日期，不回落到今天。
- 跨页正确传递日期：从今天页的「另有 N 项…查看今天全部」进入按日期，仍是当前选中日。

## 3. 详情可直接改高频字段（修正“看着能点却没行为”）

- 只读详情里的 **截止、优先级、日历、提醒、重复、计划执行** 现在都是真控件，点开即改、立即写回并持久化。
- 截止是日期 + 可选时刻的两段式，可清除；只写日期时不写入任何时刻。
- 优先级沿用唯一尺度（无 0 / 低 9 / 中 5 / 高 1），写的是真实字段。
- 计划执行交给原有的唯一计划入口（重复待办先选实例，返回仍是原抽屉）。
- 标签 chip 与「添加」、子任务「添加」在只读详情里也直接可写，不再要求先点「编辑」。
- 只读的优先级摘要不再画四个像按钮的 chip，只显示当前档位。
- 复杂联合编辑仍走「编辑」；保存语义未变（编辑态改动先落草稿，保存才写）。

## 4. 退出与返回一次一层（修正多层叠着一起关）

- Esc 的优先级改为：最上层浮层 → 新建页 → 有未保存改动的编辑抽屉 → 其余交给原有逻辑；每按一次只退一层。
- 新建页：没填内容直接离开，有内容先确认「离开这张表单？」（桌面与手机同规则）。
- 编辑抽屉有改动时先确认「放弃未保存的修改？」，无改动自然退出。
- 取消不产生业务数据修改：本轮新增的字段是即时保存的独立字段，取消路径不触碰它们。

## 5. 隐藏已完成（补齐正式产品已有偏好）

- 设置 · 通用新增「隐藏已完成」开关，写入偏好并随快照持久化，刷新后保持。
- 今天 / 待办 / 两个「已完成」分组按这个偏好隐藏；关闭后恢复。

## 6. 节气、节假日、调休（补齐正式产品已有标记）

- 日期表面统一渲染：月格、周/日视图的星期头、手机日历日期带、手机月格；今天页头也显示当天标记。
- 节气按名称（立冬、小雪…）；法定假日标「休」，调休补班标「班」，都带完整 `title`。
- 标记只是日期事实的注记，不拦截点击：点月格里带标记的那天仍进当天。

## 7. 日历：固定的星期头与“安排已有待办”

- 周视图的星期头、全天行、截止行固定在滚动容器顶部，纵向滚动时不再丢失“哪一列是哪天”。
- 月视图的星期行同样固定。
- 日历顶栏在「＋ 新建日程」旁补「＋ 安排待办」：选一条真实待办（重复的先选实例），落到计划选择器；只写计划，不改截止。

## 8. 通知延后（补齐正式产品已有的通知动作）

- 「发送测试提醒」的系统通知卡新增「延后 1 小时」，与正式产品的 snooze 语义一致：**只移动提醒**，截止日期与时刻不变。
- 延后写入的是绝对提醒时间，可从详情里继续修改。

## 9. 待办信息架构

- 「待办」默认范围改为 **全部**；未安排成为同一页里的快捷筛选，按日期是浏览方式。三个视图顺序为 全部 / 未安排 / 按日期。
- 今天页的「无日期」不再占三行任务位：收成一行入口「无日期 N 项 · 去未安排」，计数仍真实。
- 按日期视图仍只显示与选定那天相关的事项（计划执行 / 截止 / 当天日程背景），无日期只作为跳转入口。

## 9.1 独立 Review 后的修正

- 深色主题下 `.tool.primary` 原先把纸色字压在墨色底上（等于隐形）；按主按钮真实对比改为「浅墨底 + 深字」，新建页/新建日程的主按钮同样生效。
- 详情只读行不再叠加第二个 chevron（原行自带一个），「无优先级」也不再画多余箭头。
- 今天页删掉重复的页头「新建」，只留顶栏一个主入口。

## 10. 设置

- 设置首页从「重复一遍分区导航」改为真实概览：待完成 / 逾期 / 日历数 / 标签数四格，加「需要你处理」列表；没有待处理项时明确写“没有待处理的事项”。
- 删除面向设计人员的说明文字（如「左栏切换分区；右栏只放这一组的具体设置，不再重复分区名」），改为产品语气。
- 账号与自托管同步统一为同一套表达（服务器、设备、冲突），不再在首页重复链接。

## 11. 第二轮修复（2026-11-28）

1. **统一新建入口**：手机今天/待办/日历的页头「＋」是同一个控件（隐藏各页悬浮＋）；桌面统一顶栏「＋ 新建」。日历页头保留「新建日程」，但它是**单一意图**的场景快捷创建（直接进日程表单并带浏览日期），不再和顶栏开同一个二选一表。
2. **空白时间槽**：先问「新建日程 / 安排已有待办」，两半都继承点击的日期与 15 分钟对齐的时间段；「安排已有待办」走统一调度器 `Proto.scheduleTodo`，重复待办先选实例，写入的分配日期/时间与表内承诺一致。
3. **新建上下文**：日历页与按日期视图用浏览日期；当天预填下一个整点（演示时钟 15:00 → 16:00–17:00），其他日期 09:00–10:00；上下文只消费一次，取消或离开新建页即清空（键盘 `N`/`E` 与旧 AI 入口同样不继承残留草稿）。
4. **重复规则直改**：只读详情的「重复」不再原地写系列，改为进入真实编辑态（草稿 → 「保存到整个系列？」确认 → 写锚点与实例），取消不会改变系列。
5. **通知延后**：改为提醒时间 = 当前时间 + 1 小时（Flutter 语义），截止、截止时刻与相对提醒都不变。
6. **隐藏已完成**：移入待办页的筛选/显示菜单（桌面浮层 + 手机筛选弹层），设置·通用入口删除；手机日历的「显示日历」弹层不会出现该开关。
7. **事件标签**：日程详情显示事件自己的标签（此前把日历名当标签画出来、并标成"只读"），编辑态可增删；手机日程/待办编辑行有「编辑」入口，走同一个标签选择器，保存才写入。
8. **事件附件**：只读日程详情也列出真实附件行（名称/状态/大小），编辑态可上传到草稿。
9. **重复间隔与起点**：重复选择器支持任意「每 N 天/周/月/年」；「重复开始」只在已有锚点时出现，写入 `repeatAnchor`，日历投影与实例选择器都从同一锚点计数；ICS 导入导出保留 `INTERVAL=N`。
10. **ICS 与 Flutter 对齐**：导出写 UID、VTODO PRIORITY/STATUS；**不写 VALARM**（Flutter 导出器同样不写，先前自加的已移除）。
11. **小组件主题**：深色主题下小组件卡片与展示页真实变深，与"跟随应用明暗主题"的文案一致。
12. **备份文案**：明确"附件以索引记录，本体不随包"，不再暗示 ZIP 语义。

## 12. 功能覆盖核查落地的改动

逐项结论见 `DAYS_PARK_R7_COVERAGE_AUDIT.md`。落地为代码的只有真实缺口：日程标签可编辑、事件附件可见、任意重复间隔、重复起点被投影消费、ICS 字段补齐、小组件深色生效。同步、设备管理、MCP 授权、国际化、系列时区、ZIP 备份本体维持原型的模拟边界，只把不准确的文案改诚实。

## 真实剩余问题（第二轮更新）

1. 新建日程的默认时段是"当天下一个整点 / 其他日 09:00–10:00"，不是按真实空档搜索；这是刻意保留的简单规则（不新增智能排期）。
2. 节气与节假日是 2026 年的对照表，不是逐年推算；换年份需要补表。
3. 隐藏已完成只影响列表分组显示，不影响今天页头的「N 已完成」计数。
4. 系列时区由设备决定、原型不提供时区选择（与 Flutter 一致）；ICS 的 `TZID` 不写出。
5. ZIP 备份与附件本体是模拟边界：原型导出 JSON 快照，附件只有索引。
6. Esc 层叠依赖浮层记录自身；非原型自绘的系统级弹窗不在规则内。
7. 月格条目上限仍按高度实测（3–7），窗口很矮时仍会 +N。
8. 通知延后写入的重排时间只在 toast 与数据里体现，没有单独的"已延后到…"持久表面。
9. 同步、通知投递、原生小组件、MCP 授权、国际化仍是原型模拟（既定边界）。
10. 只在 Chrome 验证；未做无障碍审计与 Safari/Firefox 验证。
