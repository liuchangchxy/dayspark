# DaySpark 第三轮验收记录（2026-11-26）

> 目标：保护现有产品能力（恢复被 v1 误删的真实能力）＋ 修复 17 项已确认的数据语义缺陷。
> 判定口径：只认**真实连续操作及其数据结果**；不认渲染数量、控件接线率、JS 异常数。
> 基线：Flutter `ui/converge@b9b7dc39`（PR #113，未改动）；设计/原型第二轮 PR #115 / `6a00c5f5`。
> 本记录的数据来自 headless Chrome + CDP 对**最终构建产物**（15 个原型脚本、`dayspark-spec.html` + `host.js` + `flows-*.js`）的真实点击与 `window` 数据断言。

## 二、连续操作验收（13 条，按数据结果）

| # | 连续操作 | 实测数据（最终构建） | 结论 |
|---|---|---|---|
| 1 | 新建每日重复任务 → 完成今天 → 看明天 → 撤销 | `doneInstances=['rtest@2026-11-20']`；`isInstanceDone(明天)=false`；撤销后 `doneInstances=[]` | 通过 |
| 2 | 一个待办安排两段（09:00–10:00 / 14:00–15:00） | `plans` 两段均 `active`；`plansOn('2026-11-20')` 返回 `[[540,600],[840,900]]`；取消一段后仅剩一段且待办仍存在 | 通过 |
| 3 | 安排重复待办的某一次（11/27）→ 看其他实例 | 计划带 `occurrenceDate=2026-11-27`；`plansOn` 仅 11/27 出现；12/04、12/11 为空；`repeatAnchor` 不变 | 通过 |
| 4 | 改截止 → 取消 → 重开；只写日期保存 | 取消后源 `due=2026-11-20`；日期模式保存 `dueTime=''`（无 18:00） | 通过 |
| 5 | 四档优先级：新建/显示/筛选 | 存储 无0 / 高1 / 中5 / 低9；行徽标高/低；筛选“高”只命中 1；详情 chip 高亮正确 | 通过 |
| 6 | 删除待办 → 回收站恢复 | 恢复对象含 `cal/tags/note/due/subtasks/plan`；回收站行消失；预置行恢复后也不再出现 | 通过 |
| 7 | 删除 → 清空回收站 → 刷新 | 运行时 `TODOS` 与 localStorage 均无该 id；`purgedIds` 记录；预置 3 行标记移除 | 通过 |
| 8 | 删单次（11/13）→ 删及以后（12/04）→ 恢复及以后 | `state.skipped=['weekly@2026-11-13','weekly@2026-12-04']`；恢复后单次仍不出现，11/13 仍被删 | 通过 |
| 9 | 跨午夜日程 23:30→01:30 → 导出 ICS → 再导入 | 导出 `DTSTART:20261123T233000` / `DTEND:20261124T013000`；导入回 `start=23:30,end=01:30,endDate=2026-11-24`；RRULE 保留 | 通过 |
| 10 | 待办导出 ICS → 导入 | `DUE:20261124T013000` / `DUE;VALUE=DATE` 往返；VTODO 的 RRULE/备注/标题保留 | 通过 |
| 11 | 模拟同步冲突 → 本地 / 服务器 / 合并 | 本地：保留本地标题备注；服务器：写入服务器标题/备注/优先级 9；合并：本地标题 + 两段备注 + 优先级 9；刷新后一致 | 通过 |
| 12 | AI 连续两条建议 → 点较早一条的“安排时间” | 目标锁定该条 `act.todoId`（整理报销单）；写入后只有该待办的 `plans` 增加，另一条不变；旧消息 chip 的 `data-msg` 不指向最后一条 | 通过 |
| 13 | 保存失败 → 输入保留 → 重试 | 失败时 `variant='save-error'`，标题输入仍在，源对象未写入；重试后源对象写入新标题 | 通过 |

补充（第三轮恢复能力专项）：

| 能力 | 实测数据 | 结论 |
|---|---|---|
| 遗漏实例补完成 | 遗漏 `['2026-11-06','2026-11-13']`；完成 11/06 后 `missed=1`、`doneInstances` 增加；撤销后 `missed=2` | 通过 |
| 计划取消/失效/历史 | 取消一段 → `state='cancelled'`，`historyOf` 可见，待办未删；完成待办后 16:00/19:00 段 `invalidated`，09:00 已开始段保留；撤销完成不恢复失效段 | 通过 |

## 三、17 项缺陷处理

| # | 缺陷 | 处理文件 | 实测结论 |
|---:|---|---|---|
| 1 | 清空回收站只删标记、对象复活 | `flows-v3-data.js` | 清空后刷新，运行时与 localStorage 均不存在 |
| 2 | 同步冲突三选不写数据 | `flows-v3-ai.js` | 三路径分别写入不同正确字段；空选被拒；刷新一致 |
| 3 | 优先级数值与母版不一致 | `flows-v3-capture.js`、`flows-v3-pickers.js` | 四条新建 → 0/9/5/1；筛选/显示/详情一致 |
| 4 | 只写日期带入 18:00 | 截止弹层重写 | 日期模式 `dueTime=''` |
| 5 | 嵌套日期选择器后取消外层仍保留 | 快照/回滚 | 取消后 draft 与源都回到原值 |
| 6 | 快速添加固定 15:00–16:00 | `Proto.quickAdd` | “明天下午三点”→ 11/21 15:00；无时间 → 不写日期/计划 |
| 7 | 定时事件不能跨午夜 | 槽位 + 表单 | 23:30→01:30 存为两天跨度，两天均可见，时间轴不出负块 |
| 8 | 无锚点可选相对提醒 | 提醒选择器 | 无锚点全部禁用；有计划后恢复 |
| 9 | ICS 导出丢时刻/结束/重复 | `buildICS` | DTSTART/DTEND/LOCATION/DESCRIPTION/RRULE/折行/CRLF |
| 10 | ICS 待办无日期、不可往返 | VTODO 导出/导入 | DUE（含时刻）、备注、RRULE 往返一致 |
| 11 | 恢复预置回收站行仍留在回收站 | `trash-restore-v2` | 恢复后行消失、属性完整 |
| 12 | 恢复系列清空 skip | 恢复逻辑 | `skipped` 原样保留，单次删的不复活 |
| 13 | AI 旧消息动作指错对象 | `flows-v3-ai.js` | 每条消息自己的 `data-msg`；点旧消息只改它自己的待办 |
| 14 | 掩码 Key 被当成非法输入 | `flows-v3-ai.js` | 掩码/留空 = 保留；新值替换；清除清空 |
| 15 | 搜索硬截断 6/5 | `flows-v2-search.js` | “显示更多（共 N）/收起”，展开后 8 个日程全出现，键盘仍可用 |
| 16 | localStorage 失败静默 | `Proto.save` 覆盖 | 失败横幅 + 可重试；成功后横幅消失 |
| 17 | 只读兜底掩盖未接线控件 | `flows-v3-ai.js` fallback | 产品页未接线控件 `disabled` + “未实现”；样张明确“设计样张”；产品路由 0 死控件 |

## 五、剩余边界（不影响本轮判定）

- 跨设备同步、真实通知投递、原生小组件仍为**原型模拟**；这是项目既定边界，不是能力删除。
- 重复待办的实例级跳过/仅此次删除按真实领域契约不提供；已提供实例完成、遗漏补完成、计划取消与失效。
- 计划执行随待办进快照/备份；同步冲突的原型只模拟 `title/note/priority` 三类字段，计划执行记录的跨设备同步留在 Flutter 阶段按领域写入器实现。
