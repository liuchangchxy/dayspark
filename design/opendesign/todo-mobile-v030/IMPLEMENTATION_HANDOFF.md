# IMPLEMENTATION_HANDOFF — 交付给正式 Flutter 实现的边界说明

> 面向要把 `final/` 落到 DaySpark 正式源码里的工程师。
> 本文**不写具体 Flutter 实现代码**，只规定：改哪些地方、按什么顺序改、哪些不能动、验收标准是什么、有哪些坑。
> 设计细节一律以 `DESIGN.md` 为准；本文出现冲突时，以 `DESIGN.md` 为准并回来修本文。

---

## 1. 本轮设计做了什么、没做什么

**做了**：重新设计了待办 tab 内三个区域的**呈现方式与交互模型**——主页面骨架、Quick Create、Full Create/Edit，以及它们之间的状态流转。

**没做**：
- 没有新增、删除或修改任何业务能力。字段、校验、同步、存储、提醒调度逻辑全部保持原样。
- 没有改动 Todo / Event 的区分，没有改动 `dueDate` / `TaskAllocation` 的语义。
- 没有改动今天 / 日历 / 待办的一级导航。
- 没有引入新的设计令牌或私有控件体系。
- 没有进入正式实现。本轮产物是设计与可点击原型。

## 2. 允许修改的范围

| `android/`、`test/` 中的非布局断言、业务测试 | 非本轮范围 |

## 3. 建议的实施顺序

按「先修骨架、再修创建流、最后修表单」推进，每一步都可独立验证、独立回滚。

### 阶段 1 · 骨架（收益最大，风险最低）
1. 新增**视图段**组件（`SegmentedButton`，42dp，三项 + 计数），绑定既有 `todosViewProvider`。
2. 新增**日期带**组件（8 格，52dp），绑定一个新的选中 `LocalDate` state。
3. 把两者插入待办 tab 顶部，替换现有的 view-switch Chip 行。
4. 校验：四个视图来回切换，页面高度不跳变（用 golden test 或手动对比）。
5. 删除旧的内联 `TodoQuickAdd` 入口，创建入口统一为右上角按钮。

**验收**：现状截图里 36dp 的 Chip 与「按视图增删控件导致整页跳动」两个问题消失。

### 阶段 2 · Quick Create
1. 用 `showModalBottomSheet` 实现 Quick Create，26sp 标题 + 钴蓝下边框。
2. 实现五格属性条，顺序固定 `计划执行 / 截止 / 提醒 / 日历 / 更多`。
3. 打通到 Full Create 的跳转，**携带标题与已设属性**。
4. 修掉既有的标题丢失路径：原 `_openFullForm()` 未转发 `_controller.text`，改为显式传参。
5. 移除所有静默默认值：`dueDate` 不再隐式设为今天，`calendarId` 不再取 `calendars.first.id`，改为 UI 明示。

**验收**：从 Quick Create 进 Full Create，标题仍在；未设置任何属性时保存，不产生隐藏的 `dueDate` 与 calendar 落值。

### 阶段 3 · Full Create / Edit
1. 拆成五个折叠分组，顺序 `计划执行 / 截止 / 提醒 / 整理 / 内容`。
2. 实现「有值自动展开」规则。
3. 子任务、附件迁到二级页面，主表单只留摘要行。
4. 编辑页底部三动作，其中「安排执行时间」使用强调样式。
5. 重复系列编辑的三选一 Sheet。

**验收**：新建态首屏只有五行摘要；编辑一条属性齐全的待办，首屏直接看到要改的东西。

### 阶段 4 · 边界状态
按 `DESIGN.md` §7 逐条实现，重点是小屏降级、键盘避让、同步失败横幅。

## 5. 已知的坑

1. **`_openFullForm()` 的标题丢失**（`AUDIT.md` P4）。这是现存代码里的真实缺陷：`_controller.text` 从未转发。修的时候要连带检查草稿状态是否也被丢弃。
2. **内联 `TodoQuickAdd` 的回车提交**。它目前会静默写入 `dueDate` 与 `calendars.first.id`。删除这个入口时，确认没有别处依赖它的回调。
3. **粘性分组头与日期带的 z-order**。两者都可能吸顶，需要明确日期带不参与滚动（它是固定槽位），否则会出现双层粘顶互相穿透。
4. **视图段与日期带的正交组合**。「今天 + 全部日期」是不合法组合，需要在 state 层归一化，不要留到 UI 层判断。
5. **周范围边界**。日期带显示「今天所在周」，跨年/跨月周需要正确处理，不要出现 8 格里有空格的情况。
6. **平板/折叠屏**。`kMasterDetailBreakpoint = 1180` 以上转左右分栏，此时日期带是否保留需要产品确认——建议保留，因为它同时承担「限定日期」的职责。
7. **字体缩放 200%**。Design 规定了降级规则，但 200% 超出降级表的覆盖范围，需要额外验证：胶囊可能挤成两行，行的最小高度兜底是否仍然可点。
8. **旧 golden test**。布局变化会打破现有截图测试；先跑一遍基线再改，避免把无关 diff 混进来。

## 6. 后续可探索（不在本轮范围）

- **Concept C「时间轴优先」** 的完整形态。它把 `TaskAllocation` 作为主组织轴、把「未安排」做成可拖动托盘，语义表达最彻底，但触控稳定性与小屏适配不过关。建议作为「日历视图」或「计划模式」独立探索，不要替换主列表。
- **Concept B「分桶清单」** 的分组思路（逾期 / 今天 / 明天后 / 无截止）可以作为一种可选的排序模式叠加在现有分组之上，前提是不改变顶段槽位。
- **草稿策略**。Quick Create 意外关闭后是否保留草稿，本轮未规定，需要产品决策。
- **搜索**。AppBar 已预留搜索图标位置，但本轮未设计搜索结果页。
