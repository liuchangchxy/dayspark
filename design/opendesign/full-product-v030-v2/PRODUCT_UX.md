# DaySpark 产品 UX 规范

**版本：** v030-v2
**设计基线：** `origin/main @ 5f48ad563cb1d242106a15aa19b73ab52ee13390`
**配套原型：** `prototype/mobile.html`、`prototype/desktop.html`、`prototype/widgets.html`

---

## 1. 产品立场

DaySpark 不是项目管理工具，也不是日历皮肤。它解决两个互相纠缠的问题：

1. **我今天真正需要处理什么？**（今天）
2. **我的时间怎样安排？**（日历）

待办页回答第三个问题：**我有哪些任务，以及它们如何组织？**

这三句话决定了所有页面：今天不做成第二个待办列表，日历不做成第二个今天，待办不承担时间轴职责。

### 1.1 设计原则

- **先决定，再装饰。** 每个页面首屏必须回答一个问题；不能回答的问题移到次级层。
- **时间只有两种。** 截止是 deadline；计划执行是真正占用时间轴的安排。两者可以同时存在，也可以互相独立。
- **安静优先。** 不使用大面积渐变、玻璃、无意义卡片、到处阴影、巨大圆角。
- **结构大于数量。** 大屏/大组件不是多放几行，而是改变信息结构。
- **状态必须可见。** 选中、完成、逾期、未安排、同步中、未启用，都要有明确视觉与文案。
- **单手可达。** 手机主要操作落在底部 1/3；触控目标不小于 48dp。
- **原型必须能走通。** 设计稿上的每一步，都要能在原型里点出来。

## 2. 对象模型

| 对象 | 定义 | 不是什么 |
| --- | --- | --- |
| Todo | 一件要完成的事，可有截止、计划执行、提醒、重复、子任务、标签、所属日历 | 不是日程；不天然占用时间轴 |
| Event | 一段被占用的时间，有开始/结束、地点、日历 | 不是待办；完成状态不适用 |
| Calendar | 分组与颜色容器 | 不是标签；不表达任务属性 |
| Tag | 横向属性 | 不承载时间；不是日历 |
| TaskAllocation | Todo 的一次计划执行（开始/结束） | 不是截止；不改变 dueDate |
| 未安排 | 未完成、未删除、且没有 effective planned execution 的 Todo | 不是“没有截止” |

### 2.1 时间语义（冻结）

- `dueDate` = **截止**。可以只有日期，也可以带时间。没有时间时不显示 `00:00`。
- `TaskAllocation` = **计划执行**。出现在日历与今天的时间轴里。
- **未安排** = Todo with no effective planned execution。与是否有截止无关。
- 一个 Todo 可以“有截止但未安排”，也可以“已安排但无截止”。
- 逾期只由截止决定：`due < now` 且不是今天，且未完成。

### 2.2 文案对照

| 概念 | 使用 | 禁止 |
| --- | --- | --- |
| 截止 | “截止 11月10日 18:00” | “到期”“deadline 时间” |
| 计划执行 | “计划执行 15:00–16:00”“安排时间” | “执行截止”“任务时间” |
| 未安排 | “未安排 9 项” | “Inbox”“收件箱”（中文界面） |
| 日程 | “新建日程” | “事件”“event” |
| 已完成 | “已完成 2” | “归档” |

## 3. 信息架构


- 底部三项，固定，不因页面滚动隐藏。
- 搜索、设置、AI 不进入底部导航。

## 4. 今天

### 4.1 目标

用 3 秒回答：现在在做什么、接下来是什么、今天必须完成什么。没有安排时，帮助用户从“未安排”里挑一件，而不是展示空白。

### 4.2 结构

```
[正在进行 / 当前日程]        焦点卡
接下来                        按时间排序的日程 + 计划执行
今天截止                      没有计划执行的截止项
已逾期                        按截止时间升序
已完成 N                      默认折叠
[手机] 查看未安排 N 项
```

桌面在右侧显示“未安排”栏；选中任意待办时，右栏切换为详情，关闭后回到未安排栏。

### 4.3 排序

1. 正在进行：开始时间升序。
2. 接下来：开始时间升序；同一时间日程优先于计划执行。
3. 今天截止：截止时间升序；无时间的按当天结束处理。
4. 已逾期：截止时间升序。
5. 已完成：完成时间倒序。

### 4.4 空状态

- 无进行中、无接下来、无截止、无逾期：
  - 标题：“今天没有固定安排”
  - 说明：“从右侧未安排里挑一件，拖到时间轴或点‘安排’。”
  - 动作：查看未安排 / 新建待办。
- 没有未安排：右栏文案“全部待办都已经安排好时间。”
- 没有已完成：不显示已完成分组。

### 4.5 行语义

- 复选框：48dp 触控区、22dp 视觉圆环；整行也可点进入详情。
- 标题：15px，最多两行。
- 第二行：`计划执行 15:00–16:00`（中性）· `截止 11月10日 18:00`（暖色）· `逾期 11月9日 18:00`（danger）。
- 日程行：左侧时间列 + 标题 + 时间范围 / 地点。
- 计划执行行：空心方框标记 + “计划执行”字样，不使用实心日历点。

## 5. 日历

### 5.1 目标

回答“我的时间怎样安排”，让日程、计划执行、截止三者在同一时间语境里被理解，但不混淆。

### 5.2 视图

#### 月（手机与桌面共用结构）

- 7 列；周一开始；固定 6 行（42 格），非本月日期降低透明度。
- 每格最多：2 条日程 + 1 条计划 + 1 条截止。桌面格高 96；手机只显示日期与最多 3 个点，避免 7 列里塞文字。
- 今天：日期数字用 primary；格背景不变，避免整块高亮。
- 手机：点击某天，在月历下方更新当天议程；议程按时间排序并合并日程、计划执行与截止。
- 桌面：点击某天进入天视图并定位该日。

#### 周（手机）

- 顶部 7 天日期条；超出 412dp 时每格至少 48dp，320dp 下压缩为等分列。
- 主体是 **7 天议程**，不是 7 列时间网格：每天一个分组，头部为“周几 · 日期”，右侧是条目数。
- 组内按时间合并日程、计划执行与截止；已同时有“计划执行”的待办不再重复出现，截止信息并入计划行。
- 点击日期分组头部进入该日的天视图；点击条目进入日程或待办详情。

#### 周（桌面）

- 头部：周一…周日 + 日期；今天用 primary。
- 截止带：独立一行，列出每天最多 2 条截止项，暖色文字，行首“截止”。
- 时间轴：8:00–22:00；每小时 56px。
- 日程：实心左边框（日历色），浅色背景；高度不足 44px 时只显示标题。
- 计划执行：灰色背景 + 空心方框，文案“计划 · 时间”。
- 重叠：同一时间簇内并排分栏；宽度按簇内最大列数分配；非重叠事件占满整列。
- 当前时间：2px 暖色线，跨今天所在列，不拦截点击。

#### 天（手机与桌面）

- 单列时间轴，8:00–22:00，每小时 56px；最大宽度 720。
- 顶部截止带（若有）；截止不占用时间轴。
- 日程与计划执行按真实起止时间定位；同一时间簇并排分栏。
- 点击空白时间段新建日程，预填该日该小时。
- 30 分钟日程块按真实比例约 28px 高，是触控尺寸的已知例外。

### 5.3 工具条

```
[日 | 周 | 月]  [今天]  [‹]  [›]
```

- 手机：工具条只保留上述控件，新建日程在页面顶栏；320dp 下分段控件独占一行，今天与前后按钮排第二行。
- 桌面：主栏顶部显示范围并带新建日程。
- 不显示无标签的 ISO 周数。

### 5.4 空状态

- 当天无日程/计划：“这一天没有安排”，提供“新建日程”。
- 截止带为空：整行隐藏，不显示空白带。

## 6. 待办

### 6.1 目标

让用户看清任务的组织方式：哪些未安排、哪些全部、哪些按日期。不是第二个今天。

### 6.2 手机

- 页面标题表达当前视图（未安排 / 全部待办 / 按日期）。
- 视图切换使用明确的 segmented control，选中项为 surface + 阴影/描边，不能只靠字重。
- 列表行：复选框、标题、元信息、日历色点。
- 列表顶部提供“添加待办”输入/按钮。
- 已完成默认隐藏；列表底部或工具栏提供“显示已完成”。
- 筛选：日历、标签、优先级；筛选按钮必须有文字或明确的图标 + 数量。

### 6.3 桌面

- 列表 396px + 详情右栏。
- 列表顶部：视图分段 + 计数 + 内联快速添加（回车保存）。
- 行右键菜单：完成、安排时间、编辑、移到回收站。
- 选中行使用 `primary-soft`；详情顶部可关闭。
- 窄窗（<1180）：详情改为覆盖层；<1000：侧栏折叠为图标。

### 6.4 空状态

- 未安排为空：“没有未安排的待办。所有任务都已排进时间。”
- 全部为空：“还没有待办。用上面的输入框添加第一件。”
- 按日期为空：“这一天没有待办。”

## 7. 创建与编辑

### 7.1 快速创建（手机）

底部弹层，首屏字段：

1. 标题（自动聚焦）
2. 截止 chip（可选）
3. 计划执行 chip（可选）
4. 提醒 chip（可选）
5. “更多”展开：优先级、日历、标签、备注、子任务
6. 保存

规则：

- 只填标题即可保存。
- 截止选择器与计划执行选择器完全分开。
- 截止选日期但未选时间：显示“截止 11月13日”，不显示 `00:00`。
- 计划执行选择开始与结束；默认开始为下一个整点，时长 1 小时。
- 保存后回到来源页面并保持当前视图，底部显示约 2.4 秒的轻提示“已添加：标题”，不强制跳到待办页。
- “更多”内提供“打开完整表单”，已填标题、截止、计划执行、子任务全部带入；保存同样回到来源页并提示。

### 7.2 完整表单（手机 / 桌面）

手机入口：快速创建 →“更多”→“打开完整表单”，或编辑已有待办。桌面入口：新建待办 / 编辑。

分区：

1. **内容**：标题、备注
2. **时间**：截止日期、截止时间（可选）、计划执行开始、计划执行结束
3. **提醒与重复**：准时 / 10 分钟 / 30 分钟 / 1 小时 / 无；每天 / 每周 / 每月 / 不重复
4. **整理**：日历、标签、优先级、子任务

校验：

- 标题不能为空。
- 计划执行结束必须晚于开始。
- 截止可以早于、等于或晚于计划执行；不强制关系。
- 保存失败时保留输入并显示错误，不关闭表单。

### 7.3 日程表单

- 标题、日期、开始、结束、日历、地点、备注。
- 结束必须晚于开始；跨天允许。
- 删除在底部危险区，需确认。

## 9. 搜索

### 9.1 手机

- 全屏页面；顶部输入框自动聚焦；取消返回来源页。
- 结果分组：待办 / 日程。
- 每行显示标题 + 截止或时间；点击进入详情。
- 空查询显示最近搜索或提示；无结果显示“没有找到‘xxx’”。

### 9.2 桌面

- `Ctrl/Cmd + K` 打开命令面板。
- 空查询显示快捷操作：新建待办、新建日程、打开设置。
- 输入后显示待办 / 日程结果。
- `Esc` 关闭；点击结果进入对应视图并选中。

## 10. 设置

### 10.1 分组

| 分组 | 内容 |
| --- | --- |
| 通用 | 主题（跟随系统/浅色/深色）、主题色、语言、启动时打开、周起始日、时间格式 |
| 日历与标签 | 日历列表、新建日历、标签列表、新建标签 |
| 通知 | 通知权限、提醒声音、精确闹钟 |
| 数据 | 导入 .ics、导出 .ics、导出完整备份、合并备份 |
| 同步 | 服务器地址、账号状态、登录/注册、上次同步 |
| AI 助手 | 启用开关、服务商、模型、密钥状态 |
| 关于 | 版本、反馈、开源许可 |

### 10.2 手机布局

- 分组列表；组内行 52dp。
- 主题色：6 列圆点，每个 48dp 触控区；选中显示勾 + 外环。
- 主题：三列等宽分段，文字不换行。
- 不使用全屏单选项列表。
- 语言 / 启动时打开 / 周起始日 / 时间格式：点行弹出底部选择层，当前值带勾；选中后立即写入并回到设置。
  - 语言：跟随系统 / 简体中文（原型文案只有中文）。
  - 启动时打开：今天 / 日历 / 待办，下次启动生效。
  - 周起始日：周一 / 周日，同时作用于周条、周议程、月历首列和桌面周视图。
  - 时间格式：24 小时 / 12 小时；12 小时显示 `2:30 PM`，表单里的时间输入仍是 24 小时值。
- 同步 / AI 行的右侧状态随实际配置变化（未登录/已配置/已登录，已关闭/已启用/已就绪）。

### 10.3 桌面布局

- 左侧 200px 分区导航；右侧内容最大 720。
- 行高 52；组内分隔线；说明文字 12px。
- 语言 / 启动时打开 / 周起始日 / 时间格式用居中单选对话框，不用下拉框；选择后与手机端共享同一设置。

### 10.4 同步与 AI 状态

**同步**

```
未设置服务器 / 未登录
  → 填写服务器、邮箱、密码
  → 登录（失败：就地错误；成功：已登录、尚未同步）
  → 立即同步（同步中… → 上次同步 刚刚 / 失败原因）
  → 退出登录
```

- 注册依赖服务器支持；服务器不支持时明确说明，不伪造注册成功。
- 密码只显示“已保存”，不回显明文。
- 未登录时不显示同步成功或上次同步时间。

**AI**

```
已关闭
  → 已启用但缺模型/密钥：未配置
  → 服务商 + 模型 + 密钥齐全：已就绪
  → 试用：生成中… → 失败原因（保留输入） / 可编辑的结果
```

- 默认关闭；关闭时显示“已关闭”，不展示模型名或伪造示例结果。
- 密钥状态只显示“已保存 / 未配置”。
- 生成结果先进入可编辑草稿，不直接写入正式待办。

| `Ctrl/Cmd + K` | 打开/关闭命令面板 |
| `N` | 新建待办（不在输入框内时） |
| `Esc` | 关闭弹层 / 命令面板 / 右键菜单 |
| `Enter` | 表单保存（焦点不在 textarea 时） |
| 右键待办行 | 完成、安排时间、编辑、移到回收站 |
| 点击列表行 | 选中并在右栏显示详情 |
| 点击空白时间段 | 新建日程，预填时间 |
| 点击“今天” | 回到今天并重置日历范围 |

## 12. 小组件 UX

### 12.1 尺寸语义

| 尺寸 | 规则 |
| --- | --- |
| 小 2×2 | 只回答一个问题；不出现列表、分组、说明 |
| 中 4×2 | 3–4 条同质条目；允许直接完成；不展开分组标题 |
| 大 4×4 | 必须分组或表达时间关系；不能只是多两行 |

### 12.2 各组件

**待办**

- 小：下一件最该处理的待办 + 未安排数量。
- 中：今天的前三条（逾期 → 截止 → 计划），可勾选。
- 大：正在执行/接下来、今天截止、未安排三段。

**日历**

- 小：日期 + 下一个日程。
- 中：今天的日程列表（3 条）。
- 大：迷你月历 + 当天日程。

**时间轴**

- 小：正在进行的一件事 + 进度。
- 中：接下来三项。
- 大：8:00–20:00 时间轴，日程与计划执行分色。

**快捷操作**

- 小：一个主操作（新建待办）。
- 中：三个并排入口（待办 / 日程 / 语音速记）。
- 大：2×2 面板（再加开始专注）。

### 12.3 点击

- 组件空白：打开对应页面。
- 圆圈：完成待办，立即刷新。
- 单条：打开详情。
- 所有可点区域 ≥ 48dp（行视觉高 44dp，通过垂直内边距把点击区扩展到 48dp）。

## 13. 状态与反馈

| 状态 | 表现 |
| --- | --- |
| 加载 | 骨架行，不用全屏 spinner |
| 空 | 标题 + 一句解释 + 一个动作 |
| 错误 | 就地错误文本；保留输入；可重试 |
| 保存中 | 保存按钮禁用 + “保存中…” |
| 同步中 | 设置页状态行 + 时间 |
| 未启用 | 明确“未启用”，不显示假数据 |
| 删除 | 立即移到回收站 + 可撤销提示 |
| 完成 | 复选框即时变化；列表中保留 600ms 再移动/隐藏 |
| AI 生成中 | 按钮禁用并显示“生成中…”，失败后就地显示原因，保留输入 |
| 同步中 | 按钮变为“同步中…”，完成后更新时间；失败时就地提示 |
| 保存成功 | 轻提示“已添加：标题”，不打断当前页面 |

## 14. 无障碍与人体工学

- 触控目标：手机 ≥ 48dp；例外是日历中按真实时长渲染的短日程块（30 分钟约 28px），以及 320dp 下必须并排的 7 列日期条与月历格（横向约 40–42dp）。桌面行高 ≥ 34px，点击区 ≥ 44px。
- 字号：正文 15，次要 12–13，不依赖小于 11px 的信息。
- 对比度：正文 ≥ 4.5:1；大字号 ≥ 3:1；不把暖色文字放在浅暖底上。
- 颜色不是唯一信息：截止/计划同时有文字标签。
- 动态字号：标题最多两行，元信息可换行；按钮文字不得被截断。
- 安全区：底部弹层与操作栏避让 gesture / navigation bar。
- 单手：主要动作（新建、完成、保存）位于屏幕下半区。
- 减少动态：`prefers-reduced-motion` 下关闭过渡。
