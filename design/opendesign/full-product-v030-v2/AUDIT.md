## 2. 手机端逐区域

### 2.1 今天

**现状（源码 + 当前渲染）**

- 顶部同时出现产品名和“今天”，标题层级重复。
- 分区为“现在 / 接下来 / 今天截止 / 已逾期 / 未安排 N / 已完成”，概念是对的，但视觉上都是同一种行，截止和计划执行只靠小字区分。
- 当天没有安排时，主体塌陷，只剩“未安排 N 项”，没有一个可执行的下一步。
- “已完成”是折叠区，但折叠头和普通分区标题没有区别。

**结论：REDESIGN。**

**重设计要点**

- 一个“正在进行”焦点卡，只显示一件正在发生的事；没有就显示“今天没有固定安排”并给出两个动作：安排未安排项、查看全部待办。
- “接下来”按时间排序，日程与计划执行使用不同的行标记：日程用实心日历色点，计划执行用空心方框 + “计划执行”字样。
- “今天截止”只放没有计划执行的截止项，避免同一件事在“接下来”和“今天截止”各出现一次。
- “已逾期”单独用 danger 语义，不混入今天截止。
- “已完成 N”在底部，默认折叠，展开后是可勾选的历史。
- 手机上去掉重复标题；桌面保留页面标题。

### 2.2 日历

**现状（当前渲染 `cur-calendar.png`）**

- 头部有四层：页面标题、月份/周数、视图切换、日期条，压缩了真正的网格。
- ISO 周数“46”裸露在标题区，没有“第 46 周”的语义，也没有解释。
- 时间网格里出现提示胶囊（tip pill），遮挡时间内容。
- 出现两个“＋日程”入口，其中一个还是“＋ ＋日程”的重复文案。
- 截止项与计划执行没有清晰的视觉分工。

**结论：REDESIGN。**

**重设计要点**

- 头部收成一条工具条：`月 / 周 / 天` 分段 + 今天 + 前后 + 当前范围 + 新建。
- 范围只用一种写法：`11月9日 – 11月15日`，不出现无标签周数。
- 周/天视图上方增加独立的“截止”带，只显示截止项；时间轴只显示日程与计划执行。
- 重叠事件并排分栏；当前时间线用 2px 暖色线，不遮挡事件文字。
- 月视图的日期格只放两类摘要：日程与“计划”待办，截止用暖色文字；超出以“还有 N 项”收口。
- 新建入口只保留一个主按钮。

### 2.3 待办 / 未安排

**现状（`cur-todos.png`）**

- 顶部分段控件“未安排 / 全部”没有明显的选中态，用户不知道当前在哪个视图。
- 右上角图标按钮没有文字或可理解的分组，搜索、筛选、更多混在一起。
- “截止”chip 在视觉上像禁用按钮，实际是筛选入口。
- 列表行缺少日历归属与计划执行的结构化表达。

**结论：REDESIGN。**

**重设计要点**

- 手机不把“未安排 / 全部”做成两个平级分段；用页面标题表达当前视图，切换放在一个明确的视图菜单里，或使用底部 tab 之上的二级 chip。
- “未安排”定义为：未完成、未删除、没有 effective planned execution 的待办。
- 行结构：复选框 48dp 触控区（22dp 视觉圆环）、标题、第二行元信息（计划执行 / 截止 / 重复）、右侧日历色点。
- 截止用暖色，逾期用 danger；计划执行用中性色，避免和截止抢。
- 隐藏已完成是列表级开关，不占用工具栏主位。

### 2.4 快速创建

**现状**

- 入口多，快速创建和完整创建的关系不清楚；字段一上来就问时间，容易把截止当执行时间。
- 保存路径与返回路径不稳定，选择器关闭时会误关父弹层（本次原型开发中也复现过同类问题）。

**结论：REDESIGN。**

**重设计要点**

- 首屏只有标题输入 + 三个决定：截止、计划执行、提醒。默认不填时间。
- “更多”展开优先级、日历、标签、备注、子任务。
- 保存后停留在当前上下文：在待办页保存就留在待办页；在今天保存就回到今天。
- 截止和计划执行使用不同的选择器与文案，绝不共用“时间”一个字段。

### 2.5 完整创建 / 编辑

**结论：REDESIGN。**

- 表单分四段：内容（标题、备注）→ 时间（截止、计划执行）→ 提醒与重复 → 整理（日历、标签、优先级、子任务）。
- 手机从快速创建的“更多”直接进入完整表单，已输入的标题、截止、计划、子任务全部带入。
- 截止日期与截止时间分离；不选时间就不显示 `00:00`。
- 计划执行使用开始/结束，默认 1 小时，允许跨天。
- 保存按钮固定在底部安全区之上；删除放在底部危险区，不跟保存并排。

### 2.6 详情

**结论：REDESIGN。**

- 手机：全高详情，标题可换行，元信息分组，子任务可勾选，底部固定操作区。
- 桌面：详情在主从右栏，内容最大宽度 720；操作在内容底部而不是飘在右上角。
- 待办与日程详情使用同一套排版规则，但字段不同：待办有截止/计划执行/子任务；日程有开始结束/地点/日历。

### 2.7 搜索

**结论：KEEP 模型，REDESIGN 呈现。**

- 手机：全屏搜索页，输入即搜，结果按待办 / 日程分组，空结果给明确文案。
- 桌面：⌘/Ctrl+K 命令面板，支持“新建待办 / 新建日程 / 打开设置”命令 + 搜索结果。
- 搜索范围：标题与备注；不搜标签名作为对象，但标签可作为结果元信息。

### 2.8 设置（全部分组）

**现状（`cur-settings.png`）**

- 主题色色板在手机上竖排，一行一个，占满屏幕。
- “跟随系统 / 浅色 / 深色”分段文字换行成“跟随系\n统”。
- 分组卡片与页面背景对比弱，设置项之间缺少层级。
- 桌面仍是单列长页，没有设置导航。

**结论：REDESIGN。**

**重设计要点**

- 手机：分组列表 + 组内行；主题色使用 6 列小圆点，固定 48dp 触控区；主题分段使用等宽三列，不换行。
- 桌面：左侧设置分区导航（通用 / 日历与标签 / 通知 / 数据 / 同步 / AI / 关于），右侧内容最大宽度 720。
- 数据组明确区分：导入 .ics、导出 .ics、导出完整备份、合并备份。
- 同步组三段式：服务器地址、账号状态、上次同步。
- AI 组：启用开关、服务商、模型、密钥状态；默认关闭。

### 2.9 日历管理 / 标签 / 回收站

**结论：KEEP 功能，REDESIGN 呈现。**

- 日历管理：名称、颜色、可见性、默认日历；删除前说明影响。
- 标签：名称、颜色、使用数量；标签不是日历，不能承载时间。
- 回收站：列表 + 恢复 + 永久删除；空状态明确。

### 2.10 同步 / 账号 / 备份 / ICS

**结论：KEEP 流程，REDESIGN 呈现。**

- 同步是可选能力，不阻塞本地使用。
- 未登录时显示服务器、登录、注册三个动作，不显示“同步成功”的假状态。
- ICS 是日历交换，备份是完整数据；两者不共用“导入/导出”一个模糊入口。

### 2.11 AI

**结论：KEEP 能力，REDESIGN 入口与配置。**

- AI 不进入主导航；入口放在创建流程和设置中。
- 关闭时明确“未启用”，不显示模型名占位。
- 生成结果必须可编辑，不能直接写入正式数据。

## 3. 桌面端

### 3.1 侧栏

**现状**

- 源码已有 `WorkspaceSidebar` 与 `WorkspaceScaffold`，`kWorkspaceBreakpoint = 1000`。
- 侧栏已包含今天、日历、待办、未安排、全部待办、日历管理、标签、回收站、设置。
- 旧 Windows 构建显示的是手机底部导航，这是旧构建的问题，**不作为当前判断**。

**结论：KEEP 结构。**

- 保留 232px 侧栏、分组和底部设置。
- 选中态用 `primary-soft`，子视图（未安排/全部）用弱一层的背景。
- 日历与标签在侧栏中显示颜色点和数量。
- 1000px 以下折叠为 64px 图标栏；日历/标签区隐藏，设置仍可达。

### 3.2 主从详情

**现状**

- 源码已有 `workspaceSelectionProvider`、`TodoSelection`、`EventSelection`、`kMasterDetailBreakpoint = 1180`。
- 详情栏固定 400px。

**结论：KEEP 结构，REDESIGN 内容。**

- 列表 396px + 详情自适应，详情内容最大 720。
- 选中行使用 `primary-soft`，详情顶部有关闭。
- 详情包含标题、元信息、子任务、备注、底部操作。
- 窄窗详情变为覆盖层，左侧保留图标栏。

### 3.3 键盘与命令面板

**结论：REDESIGN（新增）。**

- `Ctrl/Cmd+K` 打开命令面板；`N` 新建待办；`Esc` 关闭；`Enter` 保存；右键待办行打开上下文菜单。
- 命令面板必须有真实结果，不做装饰性搜索框。
- 快捷键不应在输入框内触发。

### 3.4 桌面日历

**结论：REDESIGN。**

- 周视图 7 列 + 时间轴 + 截止带；重叠事件并排。
- 月视图 7×6，格高 96，最多 2 条日程 + 1 条计划 + 1 条截止。
- 天视图单列，最大宽度 720。
- 工具条只保留视图切换、今天、前后；新建在主栏右上。

### 3.5 桌面设置

**结论：REDESIGN。**

- 左侧分区导航 + 右侧内容。
- 主题、主题色、语言、启动页、周起始、时间格式在“通用”。
- 其他分组同手机，但使用更宽的行与说明。

## 4. 小组件

### 4.1 当前实现事实

| 组件 | Provider | 现有尺寸 | 关键事实 |
| --- | --- | --- | --- |
| 待办 | `TodoWidgetProvider` | small / medium / large | 三种布局都存在；medium/large 共享 header + 三个 chips；large 才分组 |
| 日历 | `CalendarWidgetProvider` | medium / large | `minWidth/minHeight = 250dp`，没有 2×2 小尺寸；只有 medium/large 布局 |
| 今天/时间轴 | `TodayWidgetProvider` | small / medium / large | 使用 `widget_action_*`；内容是日期 + 列表 + 新建按钮，不是真正的时间轴 |
| 快捷操作 | 无 | — | **当前不存在** |

### 4.2 结论

- **待办 KEEP 三尺寸，REDESIGN 结构**：尺寸变大必须改变结构，而不是只多几行；去掉 medium/large 重复的 chips，把分组留给 large。
- **日历 REDESIGN**：补 2×2 小尺寸；大尺寸用迷你月历 + 当天日程，中尺寸用当天日程列表。
- **时间轴 KEEP 三尺寸，REDESIGN 表达**：小尺寸只显示正在进行的一件事；中尺寸显示接下来三项；大尺寸显示 8–20 点时间轴。
- **快捷操作 NEW**：小尺寸一个主操作，中尺寸三个并排入口，大尺寸 2×2 面板。
- **深色 KEEP**：使用独立颜色资源，不做透明度叠加。

### 4.3 未验证

- 所有小组件均未在真实 launcher / 锁屏上安装验证。
- RemoteViews 的 `minResizeHeight`、圆角裁切、深色资源在 OEM launcher 上的表现未验证。
- 组件内的待办完成操作只在本原型中验证了状态更新，未验证 PendingIntent 链路。

## 5. KEEP / REDESIGN 清单

### KEEP

- 今天 / 日历 / 待办 三段式 IA。
- 工作区侧栏与宽屏主从结构（`WorkspaceScaffold`、`WorkspaceSidebar`）。
- `kWorkspaceBreakpoint = 1000`、`kMasterDetailBreakpoint = 1180` 的分界思路。
- 自建同步服务器、可选账号。
- ICS 与完整备份分开的产品语义。
- 小组件三尺寸的存在与 RemoteViews 路线。
- 深色模式使用独立色值。

### REDESIGN

- 今天的所有空状态与信息层级。
- 日历头部、截止带、重叠事件、桌面宽屏。
