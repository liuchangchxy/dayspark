## 建议的审查路径

1. **产品范围**：读 spec 第 0–3 节，确认“一个事实只有一个写入口”（截止 / 计划执行 / 日程时间）与 v1 不做项是否符合预期。
2. **裁定一致性**：抽查 `DAYS_PARK_209_DECISIONS.md` 中标记为“必须具备”的项，是否都能在原型里走通；标记为“暂不需要”的项是否确实没有偷偷出现。
3. **连续验收**：按 spec 第 6 节的 14 条场景连续操作，重点看：
   - 捕获 → 改类型/时间 → 保存 → 在待办/日历出现；
   - 详情编辑全部字段 → 保存失败一次 → 重试 → 刷新仍在；
   - 日历拖动改期/改时长、空白时段新建、月 `+N`；
   - 重复规则（每周一三五 + 次数/结束日期）真实展开；
   - 删除 → 回收站恢复 → 原日历/标签/子任务保留；
   - 主题/强调色/启动页切换后刷新保留；
   - 导入示例 ICS → 预览 → 报告；备份导出 → 改数据 → 合并；
   - AI 动作写入前确认；搜索高亮与键盘选择；
   - 手机：Dock 三页、整页编辑、日历周/月、设置返回栈。
4. **死路检查**：任何按钮、菜单、弹窗、选择器、抽屉都应产生可见结果；只读项应明确标注为只读。全站已移除“这一项没有更深的编辑步骤”式兜底。

## 已知边界（不是缺陷，但审查时需要知道）

- AI 回复、登录、同步、设备、冲突、通知、权限为**本地模拟**；流程、失败分支、确认步骤是真实的。
- 导入/导出/备份使用真实 File API 与本地解析，但不上传任何文件。
- 附件只记录文件名/大小，不保存二进制。
- 演示数据固定为 2026-11-20，便于复现；不是实时日期。
- 少数捕获弹层里的精细时间仍使用系统时间控件；详情编辑与计划选择器已使用设计过的时间选择器。
- 批量选择、手动排序、设置内搜索、重复待办的逐实例历史等按裁定不在 v1 范围（见 spec 第 5 节）。
